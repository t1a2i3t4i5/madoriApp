# MadoriApp

間取りを提案するアプリ

一軒家の間取りを3案生成するWebアプリ。アイデア出し用で、建築基準法・構造の厳密さは対象外。

## 概要

- 入力: 延床面積（20〜40坪）、階数（平屋/2階建て）、個室数（2〜5）、駐車場、庭、こだわり8種（対面キッチン、土間、書斎、ウォークインクローゼット、パントリー、吹き抜け、和室、ランドリー室）。「おまかせ条件」ボタンで、実現可能で3案がきちんと出る条件をランダムに選ぶこともできる
- 出力: 条件に沿った間取り3案をSVG図面で並べて比較。各案に名前・特徴タグ・実測延床・スコアを表示し、拡大表示と再生成ができる
- 「別の3案」で seed を進めると3案の組が変わる（30坪/2階/個室3 では seed 1〜30 の組がすべて異なる）。「← 前の3案」で戻れる（直近20組）。出せる案が尽きたら、その旨を表示する
- 「この条件の候補」で、候補プール（左右反転の重複は除く）から多様性を優先して選んだ上位24案を、全N案の件数つきでスコア順に見られる
- ☆でお気に入りに保存（ブラウザ内、30件まで）。2〜3案を選んで、同一縮尺で横並び比較できる。1案だけを開く共有リンク（URLハッシュの `p` パラメータ）も使える
- 拡大表示では「家具を表示」でベッド・ソファ・ダイニング・テレビボード・デスクを描き込める
- 無理な条件（平屋+吹き抜け、20坪+個室5など）は、理由と代替案を表示する。実現可能でも案が0案・3案未満になる条件では、どの階が崩れたかの理由と、実際に3案出ることを確かめた代替案を出す

## 技術メモ

- 生成: 455mmグリッド（1セル=半間）上の**固定3帯構成**（北帯 / ホール帯 / 南帯の水平3本）。アーキタイプが帯ごとの部屋クラスタ列を決め、帯の高さ・帯内の幅は clamp付き water-filling（二分探索）+ 最大剰余法で配分する。汎用のスライシング木（H/V再帰分割）は未実装
- 変種（`GEN_VERSION 2`）: 同じアーキタイプでも、帯内のクラスタ列の正順/逆順（4帯）、階段の東西、2F個室の南北配分を変えた変種を作る。クラスタは「ユニット」（主寝室+WIC、洗面+浴室+ランドリー、LDK+キッチン+パントリー、玄関+土間）として崩さずに並べ替える
- パイプライン: **候補プール**（seed と無関係。アーキタイプ × 外形上位10件 × 変種を全部組み立て → ドア/窓を隣接グラフから自動生成 → ハード制約で検証・棄却 → スコアリング → 左右反転の重複を除いてスコア降順）→ **seed による選抜**（最良から8点以内の窓で温度2の Gumbel-top-k 抽選＋多様性しきい値で3案）。プールは条件ごとにメモ化する。検証は全室への到達可能性、居室の外壁接触、最低面積。階段の両階一致と、吹抜が1FのLDK直上（x・y とも）に収まるかは組み立て時に検査。水回りの隣接はハード制約ではなくスコアで緩く評価する
- テンプレートは部屋単位ではなくクラスタ単位（玄関+土間、キッチン+パントリー、主寝室+WICなど）
- seed付き乱数で再現可能。入力+seed+genVersion はURLハッシュに保存される
- 家具・候補ギャラリー・お気に入りは生成後の追加機能。案の識別子 `planKey` は `アーキタイプ-幅x高さ-変種`（例 `1-16x14-E01000`）。v1 の旧リンク（`v=1`）は警告を出して新ロジックで開き、`p` は捨てる。お気に入りは案データ自体を保存しているので、旧バージョンのものも「旧バージョン」バッジ付きで表示できる
- 回帰テスト: v1 の正解は `legacy/index.html`（planName / planTags / feasibility のみ比較）、v2 の出力は `src/core/__fixtures__/gen-v2.json` のスナップショット。更新は `UPDATE_GOLDEN=1 npx vitest run src/core/golden-v2.test.ts`（GEN_VERSION を上げずに中身だけ変える更新は拒否される）
- v1スコープ: アーキタイプ3個（2階建て）/ 2個（平屋）、南道路のみ（道路方位は固定）、矩形外形のみ

詳しい設計と不変条件、v2 の課題は [CLAUDE.md](./CLAUDE.md) を参照。

## 開発

```bash
npm install   # 依存インストール
npm run dev   # 開発サーバー
npm run build # 型チェック + 本番ビルド
npm test      # vitest
```

React 19 + TypeScript（strict）+ Vite + Tailwind CSS v4。生成ロジックの中核は `src/core/` にフレームワーク非依存の純TypeScriptとして分離している。

## 現在の形態

**React + TypeScript 版（このリポジトリの `src/`）が正本。** Muse のスペース（静的ページ）で作った単一HTML版は原型として `legacy/index.html` に保存してあり、移植元・回帰テスト（`src/core/golden.test.ts`）の比較対象として使う。`legacy/` は削除・改変しない。
