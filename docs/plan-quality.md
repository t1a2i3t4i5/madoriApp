# 間取りの品質基準と課題（やること／やらないこと）

この文書は、生成される間取りそのものの品質についての合意事項を残すためのもの。
生成ロジックを変更する前に必ず読むこと。設計の不変条件は `CLAUDE.md`、品質の物差しはこの文書が担う。

## 出典と現状評価

- 2026-11-23、Claude（Opus）に一級建築士の目線で辛口レビューをさせた。生成サンプル6条件（デフォルト30坪・平屋25坪・40坪5室＋吹抜・部分二階ほか）を、寸法の実測つきで評価した結果。
- **総評は100点満点で25点**。住宅メーカーの初回たたき台が70点の物差し。
- 正しいのはゾーニングの大枠だけ（南にLDK、北に水回り）。寸法を測ると住宅として成立しない部屋が当たり前に混ざっていた:
- 幅0.91mの玄関・浴室・WIC、幅1.82mの個室、奥行き2.27m×長さ5.46mの主寝室
- ユニットバス最小1216（内法1.2m×1.6m）が入らない浴室が、まともな案と同スコアで並ぶ
- 40坪条件では洗面所が5〜6.9帖、子供部屋が3.5帖×3室（上下階の面積配分が破綻）
- この評価は「アイデア出し用で厳密さは対象外」という前提を踏まえても残る指摘である。「それっぽく見える」という目標自体に反する欠陥（上下で形の違う階段、壁の載っていない2Fなど）を含むため、対象外では済まない。

## 品質基準（数値）

1セル = 455mm。部屋は面積ではなく**短辺**で成立するかどうかが決まる。

### 部屋種別ごとの最小の短辺

判定の正は**セル数**とする。メートルは芯々（壁芯間）の参考値で、実際の内法は壁厚のぶん（約0.1〜0.15m）小さい。

| 部屋 | 最小の短辺 | 芯々換算 | 根拠・内法の目安 |
|---|---|---|---|
| 浴室 | 3セル | 1.365m | ユニットバスは戸建てで一般的な最小1216（内法1.2m×1.6m）。収めるには芯々で3×4セル程度 |
| 洗面 | 3セル | 1.365m | 洗面台＋人が立つ幅（内法1.37m級） |
| 玄関 | 3セル（標準4セル） | 1.365m（標準1.82m） | 靴を脱ぐ・2人が立つ |
| トイレ | 2セル | 0.91m | 日本の標準は芯々910・内法780前後 |
| WIC | 3セル | 1.365m | ハンガーパイプ0.6m＋通路 |
| 個室 | 5セル | 2.275m | ベッド＋机の配置（内法2.27m級） |
| 主寝室 | 6セル | 2.73m | ダブルベッド＋両側の通路 |
| 収納（押入型） | 奥行2セル以下 | 0.91m以下 | 奥が深いと手が届かない。通路型にしない |

### 全体の指標

- **廊下率**: 延床の5〜8%を目標（現状は約13%。全幅の中廊下が毎階強制のため）
- **収納率**: 延床の10%以上を目標（現状は2〜9%。しかも使えない0.91m幅の帯を含む数字）
- **LDK**: 対面キッチンを選んだら、カップボード0.65m＋通路0.9m＋カウンター0.65m＝2.2mに加えてダイニングテーブルが置ける奥行を確保する。家具配置でダイニングが置けない案は成立していない
- **階段**: 上下階で同じ矩形・同じ上り口／下り口。1.82mの奥行で直階段は成立しない（14段上がりなら踏面は13枚×22cm≒2.9m必要）。段数・踏面・蹴上げの幾何を持つこと
- **窓**: 角部屋は二面採光を基本とする。通風の経路（対角の開口）、水回り・階段・廊下の窓も評価対象

## やること（優先順）

いずれも生成結果が変わるため、着手時は `GEN_VERSION` を上げ、設計相談をしてから別PRで扱う（`CLAUDE.md` の手順どおり）。

1. **部屋種別ごとの最小の短辺をハード制約にする**
   - `validate.ts` に短辺チェックを足し、満たさない候補は棄却する。スコアで調整して残すことはしない
   - これだけで「成立しない案」の大半が消える見込み（レビュー試算で25点→45点）
   - 0案が増える条件が出ても、それは今まで成立しない案を出していた証拠として受け入れる。診断と代替案（`diagnoseEmpty`）で案内する
   - ただし人気条件（`CLAUDE.md` のテスト方針にある3条件）で3案が維持できることは受け入れ条件とする。維持できない場合は、条件側の扱いも含めて設計相談で決める
2. **個室にクローゼットを付属させ、余った面積を収納へ回す**
   - 余剰面積を洗面や廊下に吸収させる現行の配分をやめる。個室ごとのクローゼット（0.91m×1.82m程度）、玄関収納、階段下、パントリーへ配分する
   - 「収納」は独立した部屋としてだけではなく、部屋に付属する形で発生させる
3. **廊下と階段の扱いを変える**
   - 全幅の中廊下をやめ、ホールを最小限にする。リビング階段も選べるようにする。これは `CLAUDE.md` の不変条件「固定3帯構成」を変える話であり、汎用スライシング木が前提になる可能性が高い
   - 階段は上下同一矩形の「通路」として扱い、**階段室に開く扉は付けない**（転落防止）、**階段から寝室へ直接入るドアは付けない**。なお現状の生成ではこの2つは出ている（`stair` が VIA に含まれ、hall–stair のドアは常時付く）既知の欠陥で、解消はこの項目の実装時とする
   - 「階段の上下同一矩形」は、既知課題（高さを揃えると0案が激増する）に対する方針転換である点に注意
   - 浮いた帖数はLDK（ダイニングの置ける奥行）と玄関へ戻す
4. **窓の評価を実態に近づける**: 二面採光、通風の対角線、水回り・階段の窓
5. **上下階の壁の一致（直下率）を測る**: 2Fの間仕切りが1Fの壁の上に載っている割合。部分二階の課題として既に記録済みのものを全体へ広げる
6. **家具が置けるかを品質の判定に入れる**: ダイニングテーブル、ベッドが置けない案を落とす／減点する
7. **3案の多様性を「考え方の違い」にする**: 現状は北帯の順番と階段の東西が違うだけの実質1案。LDKの取り方・階段位置・水回りの配置が違う案を出す
8. **敷地を反映する**: 駐車場・庭の入力が配置に何も影響していない。玄関アプローチ、道路からの視線（LDKの大窓が道路から丸見えにならない）を含める
9. **洗濯動線を成立させる**: 洗う→干す→しまうの置き場（バルコニー、室内干し、ランドリー）を用意する

## やらないこと

- **厳密な構造計算・建築基準法の適合判定はしない**（従来方針の維持）。ただし上下の壁の一致や階段の幾何のような「見た目で嘘が分かる」部分は品質の対象に含める
- **最小寸法を満たさない案を、スコアの調整でごまかして出さない**。落とすものはハード制約で落とす
- **解説文で実態と違う褒め方をしない**。使えない0.91m幅の帯を数えて「収納が多め」と書く、といったことはしない（`explain.ts` の誠実さは生成の質の一部）
- **スコアの絶対値を品質の根拠として主張しない**。現状のスコアは成立しない案とまともな案が4〜6点差に収まる物差しであり、順位付けの参考にすぎない
- **外形・方位の拡張（L字、中庭、東西・北道路）を、上記の品質課題より先にやらない**。優先順位はこの文書の「やること」の順序が正

## スコア関数に足りていない観測項目（レビュー指摘）

現行の重み（採光0.20／面積0.20／縦横比0.15／廊下0.15／ドア0.15／水回り0.10／モジュール0.05）では次が測れていない。項目1〜3の着手と合わせて再設計する。

- 部屋の短辺の絶対寸法（面積適合は形を見ておらず、縦横比は相対的な比しか見ていない）
- 家具が置けるか（ダイニング・ベッド）
- 個室の収納の有無
- 二面採光と通風
- 上下の壁の一致
- 階段の成立（幾何）
- 道路からの視線（プライバシー）
- 洗濯動線
- 上下階の面積配分の妥当性（巨大な洗面と3.5帖の個室が同居しないか）

## 施主が即却下するポイント（受け入れチェック）

生成の変更を入れたら、次の質問に図の上で答えられるかを確認する。

1. 子供部屋にクローゼットがあるか
2. 玄関は狭くないか（靴を脱ぐ場所、下駄箱の置き場）
3. ダイニングテーブルはどこに置くか
4. 洗濯物はどこに干すか
5. 面積の配分は妥当か（水回りだけ巨大になっていないか）
6. 3案は考え方の違う案になっているか
