# MadoriApp 設計書

## 0. この文書について

### 0.1 位置づけ

- この文書は、MadoriApp の間取り生成と表示を「どう設計するか／どう設計すべきか」を定める規範文書とする（R-DOC-01）
- 生成される間取りの品質基準、生成ロジックの構造、保存形式の互換性規則は、この文書を正とする（R-DOC-02）
- 作業手順・コマンド・モジュール構成は `CLAUDE.md` が扱う。この文書と `CLAUDE.md` の記述が食い違うときは、この文書を正として `CLAUDE.md` を直す（R-DOC-03）
- 原型（スペース版）の `legacy/index.html` は、v1 の挙動の正解として回帰検証に使う（16章）

### 0.2 書き方の約束

- この文書は規範だけを書く。出来不出来の評価、点数、経緯（日付・PR・レビューの記録）は書かない（R-DOC-04）
- 判断の理由は書いてよい。時系列は書かない（R-DOC-05）
- 文末の使い分け:
  - 「〜とする」: 必須。満たさない設計・実装は不適合
  - 「〜が望ましい」: 推奨。外す場合は理由を設計相談で残す
- 値が確定していないものは「**暫定**」と明記する。暫定値は、根拠となる測定や相談を経て確定または改訂する（R-DOC-06）
- 値の根拠が素材にないものは、数値を置かず「未確定」と書き、方針だけを定める（R-DOC-07）

### 0.3 寸法の書き方

- 寸法の正は**セル数**とする（1セル = 455mm）。メートルは芯々（壁芯間）の参考値で、内法は壁厚のぶん（約0.1〜0.15m）小さい（R-DOC-08）
- 面積は「セル²」を正とし、畳（1畳 = 8セル²）を併記する

### 0.4 ID の付け方

- 形式は `R-<分野>-<2桁連番>`。分野は次のとおり。連番は分野ごとに振り、欠番を詰め直さない
  - DOC 文書 / GOAL 目的 / SCOPE 対象範囲 / UNIT 単位 / IN 入力 / OUT 出力 / GEN 生成構成 / SPACE 空間構成 / PROG 部屋展開 / ROOM 部屋 / WET 水回り / DOOR ドア / STAIR 階段 / VOID 吹抜 / WIN 窓 / FLOW 動線 / IDX 全体指標 / EVAL 制約と評価 / SEL 3案の選抜 / TEXT 文章 / INFEAS 成立しない条件 / DRAW 描画 / COMPAT 互換性 / VERIFY 検証 / EXT 拡張

## 1. 目的と対象範囲

### 1.1 目的

- 一軒家の間取りを3案生成し、施主がアイデア出しに使える図面として比較できるようにする（R-GOAL-01）
- 建築基準法・構造の適合判定は対象外とする（R-GOAL-02）

### 1.2 品質目標「それっぽく見える」の定義

「それっぽく見える」とは、住宅の設計を知る人が図面を見て、次のいずれにも嘘がないと感じることとする（R-GOAL-03）。

1. **部屋が成立する**: 各部屋が、種別ごとの最小の短辺・最小面積を満たし、その用途の家具・設備が収まる
2. **ゾーニングが筋に合う**: 南にLDK、北に水回り。水回りがまとまり、玄関から LDK・階段へ迷わず進める
3. **階が整合する**: 上下階で階段が同じ矩形になり、吹抜が LDK の直上に収まり、2階の壁が1階の壁の上に載る
4. **収納・動線が生活を支える**: 個室に収納があり、洗濯や来客の動線が成立する
5. **図面として読める**: 壁・ドア・窓・設備・階段の描き方が建築図面の約束に沿う
6. **3案が考え方の違いを持つ**: 並べたときに、LDK の取り方・階段位置・水回りの配置が違う

- 見た目で嘘が分かる要素（階段の上下不一致、壁の載らない2階、使えない幅の部屋など）は、「厳密さは対象外」を理由に免除しないものとする（R-GOAL-04）

### 1.3 対象範囲

**やること**

- 矩形外形の2階建て（総二階・部分二階）と平屋
- 南道路のみ（道路方位は固定）
- 部屋の寸法・隣接・動線・階の整合・採光・収納の成立
- 条件が成り立たないときの理由と代替案の提示

**やらないこと**

- 厳密な構造計算・建築基準法の適合判定（R-SCOPE-01）
- 最小寸法を満たさない案を、スコアの調整でごまかして出すこと。落とすものはハード制約で落とす（R-SCOPE-02）
- 解説文で実態と違う褒め方をすること（12章）（R-SCOPE-03）
- スコアの絶対値を品質の根拠として主張すること（10章）（R-SCOPE-04）
- 外形・方位の拡張（L字、中庭、東西・北道路）を、17章の品質改善より先に行うこと（R-SCOPE-05）

### 1.4 優先順位の原則

衝突したときは次の順に優先する（R-GOAL-05）。

1. ハード制約（部屋の成立・階の整合・到達可能性）
2. 再現性（同じ入力 + seed + 版 → 同じ結果）
3. 品質の物差し（スコア・受け入れ基準）
4. 案の多様性
5. 描画の見栄え・補助機能

- 理由: 成立しない案が多様性やスコアで上位に残ると、品質目標に反する。再現性が崩れるとURL共有・お気に入り・回帰検証が成り立たない

## 2. 用語・単位・座標系

| 用語 | 定義 |
|---|---|
| セル | 1セル = 455mm（半間）。座標・寸法はすべて整数セル |
| 畳 | 1畳 = 8セル² |
| 坪 | 1坪 = 16セル² |
| 芯々 | 壁芯間の寸法。メートル併記は芯々 |
| 短辺 | 矩形の部屋の短い方の辺（セル数） |
| 縦横比 | 長辺 ÷ 短辺 |
| 外形（footprint） | 1階の板（矩形）。幅 W × 高さ H（セル） |
| 帯 | 水平に並ぶ部屋の列。幅方向に部屋が並び、高さは帯で共通 |
| クラスタ | 一体で扱う部屋の組（玄関+土間、キッチン+パントリー、主寝室+WIC など）。テンプレートの単位 |
| ユニット | 並べ替えで崩さないクラスタ（主寝室+WIC、ランドリー+洗面+浴室、LDK+キッチン+パントリー、玄関+土間） |
| アーキタイプ | 帯ごとのクラスタ列を決める間取りの型 |
| 変種 | アーキタイプ内の差（クラスタ列の順序、階段の東西、2階個室の南北配分） |
| 候補プール | seed と無関係に作る全候補 |
| VIA | 通り抜けられる部屋の種別集合（ドアの経由点） |
| 居室 | 採光のため外壁に接する必要がある部屋 |
| 吸収セル | 帯内の余りを受ける部屋 |
| seed | 3案の選抜にだけ使う乱数の種 |
| GEN_VERSION | 生成結果が変わる変更ごとに上げる版番号（4.3） |
| 下屋 | 部分二階で1階の屋根だけが出る部分 |

- 座標系: 左上を原点、x は東向き、y は南向き（南が道路側）とする（R-UNIT-01）
- 座標は1階を基準とした共通座標とする。2階以上も同じ座標を使う（R-UNIT-02）
- 部屋は軸平行の矩形とし、整数セルの (x, y, w, h) で表す（R-UNIT-03）
- 面積・寸法の判定は常にセル数で行う。メートル・畳は表示用とする（R-UNIT-04）
- 910mm（2セル）寄せはスコアで扱い、座標のスナップはしない（R-UNIT-05）

### 3.1 入力

| 入力 | 範囲 | 既定の扱い |
|---|---|---|
| 延床面積 | 20〜40坪（320〜640セル²）。刻みは未確定 | 条件フォームで指定 |
| 階数 | 平屋 / 2階建て | |
| 2階の形 | 総二階 / 部分二階（2階建てのときだけ有効。平屋では無効） | 総二階 |
| 個室数 | 2〜5 | |
| 駐車場 | 値の形式・範囲は未確定 | |
| 庭 | 値の形式・範囲は未確定 | |
| こだわり | 8種: 対面キッチン、土間、書斎、ウォークインクローゼット、パントリー、吹き抜け、和室、ランドリー室 | 各 on/off |
| seed | 整数 | 「別の3案」で進める |

- 入力の範囲は、条件フォーム・URL の解釈・おまかせ条件の三者で同じ定義を使うものとする（R-IN-01）
- こだわりのキー・ラベルは1か所で定義し、UI・URL・生成・説明文が共有する（R-IN-02）
- 範囲外の入力は黙って丸めず、範囲内へ補正したことが分かる形で扱う（R-IN-03）
- 平屋では「2階の形」「吹き抜け」は成り立たない条件として扱う（13章）（R-IN-04）

### 3.2 入力が間取りに効く先

| 入力 | 効く先 |
|---|---|
| 延床面積 | 外形候補（W×H）、帯の高さ・幅の配分、各部屋の面積、余剰面積の量 |
| 階数 | 階の数、階段の有無、LDK・水回り・個室の階への配置 |
| 2階の形 | 2階の板の大きさ・位置（5.4）、下屋、成立条件 |
| 個室数 | 洋室・主寝室の数、階への配分、2階個室の南北配分 |
| 駐車場 | 敷地側の配置（玄関アプローチ）。反映方式は未確定。**反映するものとする**（R-IN-05） |
| 庭 | 敷地側の配置（LDK の外、道路からの視線）。反映方式は未確定。**反映するものとする**（R-IN-06） |
| 対面キッチン | キッチンの独立・カウンター形状。LDK に対面の奥行を確保する（8章） |
| 土間 | 玄関+土間クラスタ |
| 書斎 | 書斎（居室）の追加 |
| WIC | 主寝室+WIC クラスタ |
| パントリー | キッチン+パントリー クラスタ |

| 和室 | 和室（居室・畳目の描画） |
| ランドリー室 | ランドリー（水回りユニット）、洗濯動線 |
| seed | 3案の選抜のみ。候補プールには影響しない |

- 駐車場・庭の入力は、配置に何も影響しないまま残してはならない（R-IN-07）

### 3.3 出力

- 間取り3案を図面（SVG）で並べて比較できるものとする（R-OUT-01）
- 各案に、名前・特徴タグ・実測延床・スコア・解説文を付ける（R-OUT-02）
- 拡大表示、再生成（別の3案）、前の3案への復帰、候補の一覧（ギャラリー）、お気に入りと比較、PNG 書き出し、印刷を備える（R-OUT-03）
- 出力は、入力 + seed + GEN_VERSION から一意に決まるものとする（R-OUT-04）

## 4. 生成の全体構成

### 4.1 パイプライン

生成は次の段で構成するものとする（R-GEN-01）。

1. **実現可能性判定**: 入力が部屋プログラムとして成り立つかを判定する（13章）
2. **候補プールの構築**（seed 非依存）:
   1. アーキタイプ × 外形候補 × 変種を列挙し、1案ずつ組み立てる
   2. 隣接グラフからドア・窓を自動生成する（派生）
   3. ハード制約で検証し、満たさない候補を棄却する（10章）
   4. スコアを付ける
   5. 左右反転の重複を除く
3. **seed による選抜**: 候補プールから3案を選ぶ（11章）
4. **付加情報の生成**: 名前・タグ・解説文（12章）

- 候補プールは、seed と無関係に全候補を作るものとする（R-GEN-02）。理由: seed を選抜だけに使うことで、候補の全体像（ギャラリー・件数）が seed に依存せず、再現性と説明可能性が保てる
- 候補プールは条件ごとにメモ化してよい。メモ化の有無で結果を変えてはならない（R-GEN-03）
- 診断用の生成（キャッシュに入れない版）は、通常の生成と同じ結果を返すものとする（R-GEN-04）

### 4.2 決定性

- 乱数は seed 付きの決定的な乱数だけを使う。`Math.random` や時刻を生成に使わない（R-GEN-05）
- 同じ入力 + seed + GEN_VERSION からは、案の集合・順序・各案の内容がビット単位で同じになるものとする（R-GEN-06）
- 生成ロジック（`src/core/`）はフレームワーク非依存の純 TypeScript とし、React・DOM・ブラウザ API に依存しない。Node 上でそのまま動くものとする（R-GEN-07）
- 帯・セルなどの入力データは破壊的に変更しない。作業用データは関数内で新しく作る（R-GEN-08）
- 並びに曖昧さがある箇所（同点のタイブレークなど）は、決定的な順序を定める（R-GEN-09）

### 4.3 GEN_VERSION の意味

- GEN_VERSION は、**同じ入力 + seed に対する生成結果が変わる変更**を入れるたびに上げるものとする（R-GEN-10）
- 次の変更は生成結果を変えるので、版を上げる対象とする: アルゴリズム・配分・順序・ハード制約・スコアの式／重み・多様性選抜の規則・変種の列挙
- 次の変更は版を上げない: 描画のみの変更、UI、解説文の言い回しを除く表示の変更、性能改善（結果が同一のもの）
- 版を上げたときは、版別の golden を更新し、旧版のリンク・お気に入りの扱いを 15章に従って整える（R-GEN-11）
- 生成結果が変わる変更は、機能追加のついでに入れず、別の変更として扱う（R-GEN-12）

## 5. 空間構成

### 5.1 抽象要件（方式に依らない）

- 各階は、板（矩形）を隙間なく部屋の矩形で埋めるものとする（R-SPACE-01）
- 各部屋は軸平行の矩形で、隣接は辺の共有で定義する。隣接グラフからドア・窓を導出する（R-SPACE-02）
- すべての部屋は、玄関から、ドアでつながる経路で到達できるものとする（R-SPACE-03）
- 階段は上下階で同じ矩形を使う（8.3）。吹抜は LDK の直上に収まる（8.4）
- 廊下・ホールは最小限とする（9章）。全幅の中廊下を毎階強制する構成は望ましくない（R-SPACE-04）
- 部屋の幅・高さの配分は、各部屋の最小面積・最大面積・最小の短辺の範囲に収めたうえで、目標面積に近づけるものとする（R-SPACE-05）
- 余りが出たときの配分は 6.3 に従う（R-SPACE-06）

### 5.2 外形の規則

- 外形は、延床面積に見合う整数セルの矩形とし、候補を決定的な順で複数挙げる。候補数の上限は10とする（R-SPACE-07）
- 外形は矩形のみとする。L字・中庭型は拡張（17章）で扱う（R-SPACE-08）
- 道路は南とし、方位は固定する（R-SPACE-09）
- 外形の選び方（縦横比の許容など）の数値は未確定。**暫定**として、スコア（縦横比・面積適合）と部屋の最小寸法から自然に決まる範囲に限る

### 5.3 現行方式: 固定3帯構成

抽象要件の実現方式として、次を採る。方式を変えるときは GEN_VERSION を上げる（4.3）。

- 各階を北帯 / ホール帯 / 南帯の3本の水平帯で構成するものとする（R-SPACE-10）
- 1階の階段は北帯、LDK は南帯に置く（R-SPACE-11）
- アーキタイプが帯ごとのクラスタ列を決める。数は、2階建て3個、平屋2個とする（R-SPACE-12）
- 帯の高さと帯内の幅は、clamp 付き water-filling（二分探索）+ 最大剰余法で配分する（R-SPACE-13）
- 帯内の余りは吸収セルへ入れる。溢れたときは、結合できるクラスタ（玄関+土間 → キッチン+パントリー）を順に結合して再試行する（R-SPACE-14）
- 変種は、クラスタ列の順序（ユニットを崩さない並べ替え）、階段の東西、2階個室の南北配分で作る。適用後の帯構成が同一の変種は、列挙前に省く（R-SPACE-15）
- 帯の高さを seed で揺らす案は採らない。理由: 重複が増えるだけで、吹抜の整合違反が増える（R-SPACE-16）
- この方式の限界: 汎用のスライシング木（H/V 再帰分割）を持たない。リビング階段・中廊下なしの構成は、スライシング木が前提になる見込みである（17章）

### 5.4 部分二階の幾何規則

- 部分二階は、2階を1階より小さくし、1階の屋根（下屋）が出る形とする。2階建てのときだけ選べる（R-SPACE-17）
- 2階の板は1階の板に内包されるものとする（R-SPACE-18）
- 2階の板は**北寄せ**（y 方向の位置 0）とし、**階段側寄せ**とする。階段が東端なら 2階の x 位置は W1−W2、西端なら 0。理由: 階段が北帯の y=0 にあるため（R-SPACE-19）
- 1階との関係は**一辺共有の2形のみ**とする。直積（東西かつ南）は認めない（R-SPACE-20）
  - 東西下屋: H2 = H1、W2 = W1−k（k ≥ 3、W2 ≥ 9）。下屋は階段と反対側
  - 南下屋: W2 = W1、H2 = H1−k（k ≥ 3、H2 ≥ 13）
- 2階の面積割合 W2×H2 ÷ 延床は **0.35〜0.45** とする。下屋の出は3セル（1.365m）以上とする（R-SPACE-21）
- 部分二階の実現可能性の下限は、「2階の最低面積の合計 × 1.18 ≤ 延床 × 0.45」とする（R-SPACE-22）
- 座標は1階基準の共通座標とし、各階の板は階ごとの矩形で表す。外壁の判定（採光・窓・外壁描画・解説の階段側）はその階の矩形を使う（R-SPACE-23）
- LDK は1階にある前提とし、LDK に関する判定（名前の「南LDK」、解説の LDK 南判定）は1階の板で行う（R-SPACE-24）
- 延床面積は各階の板面積の合計とする。総二階では「1階の板面積 × 階数」と一致する（R-SPACE-25）
- 壁の直下率（2階の壁が1階の壁の上に載る割合）は、部分二階だけでなく全体で扱う（9章）（R-SPACE-26）
- 部分二階は吹抜との相性が悪い（2階南帯が低くなる）。成り立たないときは理由と代替案を出す（13章）

## 6. 入力から部屋への展開

### 6.1 部屋リストの作り方

- 部屋リストは、入力から決定的に作る。基本の部屋は、LDK、玄関、階段（2階建て）、ホール、水回り（浴室・洗面・トイレ）、主寝室、洋室（個室数に応じて）とする（R-PROG-01）
- こだわりは、対応する部屋・クラスタを加える形で反映する（R-PROG-02）

| こだわり | 加える部屋・クラスタ |
|---|---|

| 土間 | 玄関+土間 |

- テンプレートは、部屋単位ではなくクラスタ単位とする（R-PROG-03）
- 水回りユニットは、ランドリー → 洗面 → 浴室 の順に並べるものとする。理由: 水回りの隣接制約（8.1）を、並べ方だけで満たすため（R-PROG-04）
- クラスタ内の各部屋は、同じ階で辺を共有する（R-PROG-05）

### 6.2 階への配置

- 平屋は、すべてを1階に置く（R-PROG-06）
- 2階建ては、LDK・玄関・水回り・階段を1階、主寝室・洋室を主に2階に置く。個室の階への配分は、個室数と延床から決める（R-PROG-07）
- トイレは、階ごとの水回り隣接（8.1）を満たす階に置く（R-PROG-08）
- 階段は、1階と2階で同じ矩形で置く（8.3）（R-PROG-09）
- 2階の個室は、南北に配分する。変種の1つとして扱う（R-PROG-10）

### 6.3 余剰面積の配分の優先順位

帯・階に余りが出たときは、次の順で配分するものとする（R-PROG-11）。

1. 各部屋の最小面積・最小の短辺を満たす（満たせない案は棄却）
2. 個室に付属するクローゼット（0.91m×1.82m 程度。2×4セル）
3. 玄関収納（下駄箱）、階段下の収納、パントリー
4. LDK（ダイニングテーブルが置ける奥行）
5. 玄関（標準4セル幅への拡大）
6. 各部屋の目標面積への近づけ（最大面積を超えない）

- 洗面や廊下に余りを吸収させない。吸収させるときは、最大面積の範囲内に限る（R-PROG-12）
- 収納は、独立した部屋としてだけではなく、部屋に付属する形で発生させる（R-PROG-13）
- 上記の順序は**暫定**とする。配分の細則（各項への配分量）は未確定

## 8. 部屋どうしの関係

### 8.1 水回りの隣接（ハード制約）

- 階ごとに、次を満たすものとする。「隣接」は辺を2セル以上共有することとする（R-WET-01）
  - 浴室 → 洗面と隣接
  - ランドリー → 洗面と隣接
  - トイレ → 同じ階の浴室・洗面・ランドリーのいずれかと隣接
- キッチン・パントリーは対象外とする（R-WET-02）
- 水回りの集約（全体としてまとまること）は、緩い評価としてスコアで扱う（10.2）（R-WET-03）

### 8.2 ドアの規則

- ドアは隣接グラフから自動生成する。経由可能性は部屋種別ごとの VIA で判定する（R-DOOR-01）
- 浴室のドアは洗面とだけ付ける（R-DOOR-02）
- 階段とトイレの間にドアを付けない（R-DOOR-03）
- **階段室に開く扉は付けない**（転落防止）。**階段から寝室へ直接入るドアは付けない**（R-DOOR-04）
  - 階段は上下をつなぐ「通路」として扱い、ホール等から開口でつながるものとする
- ドア除外表は部屋種別のペア配列とし、ペアを名前順に正規化した集合で照合する。手書きの文字列キーを使わない（R-DOOR-05）。理由: 正規形と一致しないキーでは除外が効かなくなる
- ドアの形状（葉の位置・長さ・開き先・弧）は1か所で算出し、描画・家具配置・動線計算が同じ結果を共有する（R-DOOR-06）
- 葉は共有区間内に置く。最大長は1.8セル（約0.82m）とし、共有区間の34%地点を中心にクランプする（R-DOOR-07）
- 弧の半径は、葉の長さと開き先の深さの小さい方とし、弧の矩形は開き先の部屋に収まる（R-DOOR-08）
- 開き先は、片方だけ VIA でない場合はその部屋、同条件なら面積の小さい方とする。VIA どうしのタイブレークは面積 → y → x の順とする（R-DOOR-09）。ただし階段側へ開く組（hall-stair）は 8.2 の R-DOOR-04 に従い、設けない
- 同じ部屋に開く弧の矩形が重なるときは、葉を共有区間の端へ寄せる → 開き先を反対の部屋に切り替える、の順で避ける。避けられなければ既定の形のままとする（R-DOOR-10）
- 玄関の外開きは、半径を玄関の幅以下とする（R-DOOR-11）
- トイレ・キッチンでは、器具と弧が重ならないことが望ましい。トイレは外開きの特例を検討する（R-DOOR-12）

### 8.3 階段

- 階段は、上下階で**同じ矩形・同じ上り口／下り口**とする（x・y・幅・高さが一致）（R-STAIR-01）
  - 理由: 上下で形の違う階段は、見た目で嘘が分かる。階段の高さ（y）を階ごとの帯の高さに依存させない
- 階段は、段数・踏面・蹴上げの幾何を持つ。矩形がその幾何を収められることを成立条件とする（R-STAIR-02）
  - 例: 14段上がりの直階段は、踏面13枚 × 22cm ≒ 2.9m の長さが必要。奥行 1.82m の矩形では直階段は成立しない
- 階段の幾何の数値（蹴上げ・踏面・段数）は未確定。**暫定**として、上の例の寸法関係を満たす範囲に限る（R-STAIR-03）
- 階段の描画は、段と上り方向の矢印を持つ（14章）。リビング階段は選べるようにする（17章）（R-STAIR-04）
- 階段の矩形が不足するとき、1F・2F の座標一致を崩して通すことはしない。通せない条件は棄却し、診断で案内する（R-STAIR-05）

### 8.4 吹抜

- 吹抜は、LDK の直上に収まる。x・y ともに LDK の矩形内とする（R-VOID-01）
- 吹抜ありのときは、2階南帯の高さを1階南帯の高さ以下に抑える（R-VOID-02）
- 部分二階では、2階南帯の高さの上限を（1階南帯の高さ − 1階と2階の高さの差）とする（R-VOID-03）
- 吹抜と階段の間にドアを付けない（R-VOID-04）
- 吹抜は組み立て時に検査し、満たさない候補は棄却する（R-VOID-05）

### 8.5 窓

- 窓は、外壁に接する辺から自動生成する（R-WIN-01）
- 角部屋は二面採光を基本とする（R-WIN-02）
- 通風を、対角の開口の経路として評価する（R-WIN-03）
- 水回り・階段・廊下の窓も評価対象とする（R-WIN-04）
- 道路側（南）からの視線を考慮し、LDK の大窓が道路から丸見えにならないようにすることが望ましい（R-WIN-05）
- 窓の評価は、10.2 のスコア項目「採光」の拡張として扱う。評価式は未確定

### 8.6 動線

- 動線は、ドアでつながる部屋の最短経路で計算する（R-FLOW-01）
  - 来客: 玄関 → LDK
  - 生活: LDK → 洗面・浴室
- 中継は VIA の部屋を優先する。VIA だけで届かないときに限り、VIA 以外の部屋を通すことを、ペナルティを課したうえで認める（R-FLOW-02）
- 階をまたぐ区間は、階段までを描く（R-FLOW-03）
- 洗濯動線は、洗う → 干す → しまうの置き場（バルコニー、室内干し、ランドリー、クローゼット）が用意されていることで成立とする（R-FLOW-04）
- 動線の重ね表示は、拡大表示に限る（14章）

## 9. 全体の指標

| 指標 | 定義 | 目標 |
|---|---|---|
| 廊下率 | ホール面積 ÷ 延床 | **5〜8%**（R-IDX-01） |
| 収納率 | 収納面積（付属のクローゼット・WIC・収納・パントリー・玄関収納を含む）÷ 延床 | **10%以上**。ただし使えない幅（短辺 2 未満など、7.2 の寸法を満たさない帯）は数えない（R-IDX-02） |
| LDK のダイニング | 家具配置でダイニングテーブルが置けること | 必須（R-IDX-03）。対面キッチンなら、カップボード 0.65m + 通路 0.9m + カウンター 0.65m = 2.2m に加え、ダイニングテーブルが置ける奥行 |
| 面積配分 | 各部屋の面積が目標に対して妥当か。上下階の配分を含む | 水回りが肥大せず、個室が最小面積付近に偏らないこと。数値は未確定（R-IDX-04） |
| 直下率 | 2階の間仕切りのうち、1階の壁の上に載る割合 | 目標値は未確定。まず測定し、値は測定結果をもとに決める（R-IDX-05） |

- 廊下率は、スコア（10.2）では 14% を 0 点とする式で評価し、目標 5〜8% より緩い範囲を許す。目標は**設計の方向**であり、ハード制約にはしない（R-IDX-06）
- 面積配分は、ハード制約の最小面積・最大面積に加えて、スコアの面積適合で評価する（R-IDX-07）
- 収納率の算入に、使えない寸法の帯を含めてはならない。解説文も同じ基準で書く（12章）（R-IDX-08）

## 10. 制約の層と評価モデル

### 10.1 3つの層

| 層 | 性格 | 違反したとき |
|---|---|---|
| ハード制約 | 成立の条件 | 候補を棄却する。スコアで補わない |
| ソフトスコア | 順位付けの物差し | 点が下がる |
| 受け入れ基準 | 人の目での確認（16章） | 変更を入れない／直す |

**ハード制約**（R-EVAL-01）

- 全室への到達可能性（通り抜け可否は部屋種別ごとの VIA で判定）
- 居室の外壁接触（採光）
- 最低面積
- **最小の短辺（7.2）**
- 水回りの隣接（8.1）
- 階段の上下一致（8.3）
- 吹抜が LDK 直上に収まること（8.4）
- 階ごとの検証は、その階の板（5.4）に対して行う

**ソフトスコア**（R-EVAL-02）: 10.2 の7項目と、10.4 で加える項目

**受け入れ基準**（R-EVAL-03）: 16.2 の6問。加えて、人気条件（延床30坪・2階・個室3、30坪・平屋・個室3、35坪・2階・個室4）の複数 seed で3案が出ること

- 「家具が置けるか」（ダイニングテーブル・ベッド）は、ハード制約とするか減点とするかは未確定とし、**暫定**として受け入れ基準に置く。決定は設計相談で行う（R-EVAL-04）
- 振り分けの原則: 落とすべきもの（成立しない寸法・階の不整合）はハード制約、程度の差を見るものはソフトスコア、人の判断が要るものは受け入れ基準とする（R-EVAL-05）
- 最小の短辺のハード制約化によって0案になる条件が増えても、それは成立しない案を出していた条件として受け入れ、診断と代替案で案内する。ただし人気条件では3案を維持する。維持できないときは、条件側の扱いを含めて設計相談で決める（R-EVAL-06）

### 10.2 ソフトスコアの項目と重み

総合点は項目点（0〜1）の重み付き和 × 100 を四捨五入した整数とする（R-EVAL-07）。重みは**暫定**とする（R-EVAL-08）。

| 項目 | 重み | 意味 |
|---|---|---|
| 採光 | 0.20 | 居室のうち外壁に接する割合 |
| 面積適合 | 0.20 | 部屋面積 ÷ 目標面積（0.4〜1.8 にクランプ）が 1 に近いほど高い。ホール・吹抜・階段は除く |
| 縦横比 | 0.15 | 部屋ごとに 1 − (比 − 1) ÷ 3 を 0〜1 にクランプ（比 4.0 で 0 点）。ホール・吹抜・階段は除く |
| 廊下の少なさ | 0.15 | 1 − ホール面積 ÷ 延床 ÷ 0.14 を 0〜1 にクランプ |
| 動線・ドア | 0.15 | ドア数 ÷ (部屋数 × 0.62) を 0〜1 にクランプ |
| 水回り集約 | 0.10 | 水回りの中心の重心からの平均距離 ÷ (W × 0.55) が小さいほど高い。水回りが2室未満なら 1 |
| 910モジュール | 0.05 | x と w がともに偶数の部屋の割合 |

- 重みの合計は 1.00 とする（R-EVAL-09）
- 式中の定数（0.14、0.62、0.55、0.4〜1.8、3）は**暫定**とする

### 10.3 スコアは順位付け専用

- スコアは、候補の順位付けと選抜（11章）にだけ使う（R-EVAL-10）
- スコアの絶対値を、品質の根拠として UI・解説文・文書で主張しない（R-EVAL-11）
  - 理由: スコアは、部屋の短辺・家具・収納などの成立を測る物差しではない（10.4）。成立の保証は、ハード制約と受け入れ基準が担う
- UI に点数を出すときは、順位の参考であることが分かる扱いとする（R-EVAL-12）

### 10.4 スコアに加えるべき観測項目

次の項目を観測できるようにする（R-EVAL-13）。項目を加えるときは、重みを再設計し、GEN_VERSION を上げる。重み・式は未確定とする。

- 部屋の短辺の絶対寸法（面積適合は形を見ず、縦横比は相対比しか見ない）
- 家具が置けるか（ダイニング・ベッド）
- 個室の収納の有無
- 二面採光と通風
- 上下の壁の一致（直下率）
- 階段の成立（幾何）
- 道路からの視線（プライバシー）
- 洗濯動線
- 上下階の面積配分の妥当性（巨大な洗面と小さな個室が同居しない）

## 11. 3案の選び方と多様性

- 候補プールの各案は、スコア降順に並べる（左右反転の重複は除く）（R-SEL-01）
- 選抜は seed を使い、次の規則で3案を選ぶ（R-SEL-02）
  1. 最良スコアから 8 点以内の窓に入る候補を対象にする
  2. 窓の中から、温度 2 の Gumbel-top-k 抽選で選ぶ
  3. すでに選んだ案との多様性（距離）が **0.16** 以上のものだけを採る
- 上記の窓幅・温度・しきい値は**暫定**とする（R-SEL-03）
- seed は選抜にだけ使う。seed を進めると3案の組が変わることが望ましい。出せる案が尽きたら、その旨を表示する（R-SEL-04）
- 多様性は、「考え方の違い」で測るものとする。LDK の取り方・階段位置・水回りの配置が違う案を出す。北帯の順番と階段の東西だけが違う案は、実質同一案として扱う（R-SEL-05）
  - 多様性の距離の定義（どの特徴をどう重み付けるか）は、この方針に沿って設計し直す。具体の式は未確定
- 3案が揃わないときは、揃った数を出し、理由を示す（13章）（R-SEL-06）
- ギャラリー（候補の一覧）は、候補プールから多様性を優先して選んだ上位24案を、全N案の件数つきで出す（R-SEL-07）。スコアの低い案が混じりうる選び方（最遠点選択）には、スコア下限または重み付けを入れることが望ましい
- 「別の3案」の履歴は上限20組とし、URL ハッシュには入れない（R-SEL-08）

## 12. 名前・タグ・解説文の原則

- 名前・特徴タグは、案の配置と入力から決定的に作る（R-TEXT-01）
- 名前・タグ・解説文は、図面に実際に当てはまる特徴だけを書く。当てはまらない特徴・実態と違う褒め方は書かない（R-TEXT-02）
  - 例: 使えない幅の帯を数えて「収納が多め」と書かない
- 解説文は、スコアの内訳・配置・入力だけから作る純関数とし、2〜3文とする。部分二階は先頭に1文足す（最大4文）（R-TEXT-03）
- 弱点（廊下が長い・縦横比・面積適合）がある案は、必ず触れる。文数が足りなければ、階段の文と1文にまとめる（R-TEXT-04）
- 階段と個室の関係は階ごとに判定し、個室には書斎・和室を含む（R-TEXT-05）
- LDK の畳数は、キッチンが独立の案ではキッチンを含める（R-TEXT-06）
- 割合は小数1桁に切り捨てて書く（R-TEXT-07）
- 解説文の言い回し・しきい値は、1か所の定義にまとめる（R-TEXT-08）
- 文を足すときは、「当てはまる場合だけ書く」条件を先に定める（R-TEXT-09）

## 13. 成り立たない条件の扱い

- 無理な条件（例: 20坪 + 個室5、平屋 + 吹き抜け）は、黙って要素を落とさない。理由と代替案を UI に出す（R-INFEAS-01）
- 実現可能性判定は、部屋プログラムが入力の延床・階数・個室数・こだわりに対して成り立つかを調べる（R-INFEAS-02）。部分二階は 5.4 の下限（R-SPACE-22）を使う
- 実現可能でも、生成が0案・3案未満になる条件では、どの階が崩れたかの理由と、代替案を出す（R-INFEAS-03）
- 代替案は、実際に3案を返すことを確かめたものだけを、最大3件出す（R-INFEAS-04）
- 部分二階で成り立たないときは、代替の先頭を「総二階にする」とする（R-INFEAS-05）
- 吹抜が成り立たないときは「吹抜を外す」を代替に含める（R-INFEAS-06）
- 「おまかせ条件」は、実現可能で、かつ3案が返る条件だけを返す（R-INFEAS-07）
- ハード制約（特に最小の短辺）の追加で成り立たなくなった条件は、診断と代替案の対象とする。人気条件は成り立つことを受け入れ条件とする（R-INFEAS-08）
- 成り立ちにくい境界条件（0〜2案になる条件）は、診断で案内するだけでなく、生成側の改善（17章）で減らす方向とする（R-INFEAS-09）

## 14. 描画の仕様

描画品質は生成と同じくらい重要とする（R-DRAW-01）。

- 図面は SVG で描く。画面・印刷・PNG 書き出しは同じ SVG を使う（R-DRAW-02）
- 壁は、外壁と間仕切りで太さを描き分ける（R-DRAW-03）
- ドアは、葉と開き弧を描く。弧の形状は 8.2 の算出結果を共有する（R-DRAW-04）
- 窓は、外壁上の開口として描く（R-DRAW-05）
- 水回りは、浴槽・洗面台・便器・ランドリー等の器具を描く（R-DRAW-06）
- 階段は、段と上り方向の矢印を描く（R-DRAW-07）
- 和室は畳目を描く（R-DRAW-08）
- 部屋ラベルは、部屋の大きさに応じてサイズを出し分ける（R-DRAW-09）
- 部分二階の2階には、1階外形の破線と、下屋領域のハッチ、「下屋」ラベルを描く。viewBox は1階の板のままとする（R-DRAW-10）
- 家具（ベッド・ソファ・ダイニング・テレビボード・デスク）は、拡大表示で、トグルにより描き込む。配置は決定的な純関数とし、ドアの弧・対面キッチンのカウンター・部屋名ラベル・既に置いた家具を避け、置けなければ置かない（R-DRAW-11）
- 動線の重ね表示は拡大表示に限る。部屋ラベルより下に描き、凡例は図面の下端に足す専用の帯に置く（R-DRAW-12）
- 階別の坪数を、部分二階のカード・拡大表示に表示する（R-DRAW-13）
- 印刷は全階を並べる。ボタンを含む文は、文ごと印刷から隠す（R-DRAW-14）
- PNG 書き出しの文字列処理は、`$` などの特殊文字を壊さない。ブラウザ API に依存する部分と文字列処理を分ける。ObjectURL は60秒後に解放する（R-DRAW-15）
- 描画の数値（壁の太さ・フォントサイズなど）は、図面の縮尺に対する見た目で決めるものとし、この文書では固定しない

## 15. 保存と互換性

### 15.1 URL ハッシュ

- 入力 + seed + GEN_VERSION を URL ハッシュ（`c`）に保存する（R-COMPAT-01）
- 開いている1案は planKey を `p` で保存する（R-COMPAT-02）
- 総二階・平屋のハッシュ文字列は、部分二階の導入前後で変えない。`story` は、部分二階かつ2階建てのときだけ出力する（R-COMPAT-03）
- 解釈（parse）は、`story` が部分二階を表す値のときだけ採用し、それ以外は総二階として扱う（R-COMPAT-04）
- 古い版（v1）のリンクは、警告を出して新しいロジックで開き、`p` は捨てる（R-COMPAT-05）

### 15.2 planKey

- 形式は `アーキタイプ-幅x高さ-変種`（例: `1-16x14-E01000`）とする。部分二階は末尾に `-p<W2>x<H2>` を付ける（R-COMPAT-06）
- v1 の形式は `アーキタイプ-幅x高さ`（変種なし）とする。v1 の key からの再構築は行わない（R-COMPAT-07）
- planKey から案を再構築できるものとする。再構築結果は、同じ版の生成結果と一致する（R-COMPAT-08）

### 15.3 お気に入り

- お気に入りは、案のデータそのものをブラウザに保存する。上限は30件とする（R-COMPAT-09）
- 保存形式・上限・壊れたデータの復旧は1か所で定義する。ストレージへの入出力は関数を引数で受ける形にし、テストで差し替えられるようにする（R-COMPAT-10）
- 読み込み時に、案データが建物に収まる正の矩形などの整合を検査し、壊れたデータは取り除く（R-COMPAT-11）
- 旧版のお気に入りは、「旧バージョン」バッジ付きで表示する（R-COMPAT-12）
- 保存データの識別子（条件 ID）は、部分二階のときだけ部分二階を示す印を足し、総二階・平屋の既存の識別子を変えない（R-COMPAT-13）

### 15.4 データ形式の互換規則

- 総二階では、階ごとの板（`fp`）を持たない。付けると、正準ハッシュと golden が変わる（R-COMPAT-14）
- 既存データの型に項目を足すときは、任意項目とし、なければ従来の意味で読む（R-COMPAT-15）

### 15.5 版を上げたときの扱い

- GEN_VERSION を上げたら、次を行う（R-COMPAT-16）
  1. 版別の golden fixture を新しい版で書き出す（16.1）
  2. 旧版のリンク（`v` が旧版）は、警告を出して新ロジックで開く
  3. 旧版のお気に入りは、案データの表示を保ち、バッジを付ける
  4. 旧版の fixture は、版の移行検証が終わるまで残してよい
- 旧版の挙動を新版で再現することは求めない。旧版の案は、保存データから表示できればよい（R-COMPAT-17）

## 16. 検証の方法

### 16.1 golden の考え方

- golden は2本立てとする（R-VERIFY-01）
  - **v1 の正解は `legacy/index.html`**。名前・タグ・実現可能性判定を、原型を実行して比較する。生成そのものは、方式が変わった版では比較しない
  - **版別の出力は `__fixtures__/gen-v<GEN_VERSION>.json`**。生成案（複数条件 × 複数 seed）、候補プールの件数・上位10件・ハッシュ、実現可能性判定のグリッドの3案を固定する
  - 部分二階は別の fixture を持つ
- アルゴリズムを意図して変えるときは、GEN_VERSION を上げたうえで、fixture を書き出す。版が同じまま中身だけが変わる更新は拒否する。強制するときだけ明示の指定を要する（R-VERIFY-02）
- fixture の更新は、生成結果が変わったことを意図した差分として確認できる形で行う（R-VERIFY-03）
- `legacy/` は削除・改変しない（R-VERIFY-04）

### 16.2 受け入れ基準＝施主の視点の6問

生成の変更を入れたら、図の上で次に答えられることを確認する（R-VERIFY-05）。答えられない案が出るなら、変更は未完了とする。

1. 子供部屋にクローゼットがあるか
2. 玄関は狭くないか（靴を脱ぐ場所、下駄箱の置き場）
3. ダイニングテーブルはどこに置くか
4. 洗濯物はどこに干すか
5. 面積の配分は妥当か（水回りだけが巨大になっていないか）
6. 3案は考え方の違う案になっているか

### 16.3 テストの最低限

- 人気条件（延床30坪・2階・個室3、30坪・平屋・個室3、35坪・2階・個室4）で、複数の seed で3案が出る（R-VERIFY-06）
- 生成した案が、ハード制約を満たす（R-VERIFY-07）
- 同じ seed + 入力で、同じ結果になる（再現性）（R-VERIFY-08）
- ハード制約の検証は、生成側の検証とは別の独立した実装でも行う（クラスタの辺共有・階段の x 一致・吹抜 ⊂ LDK を含む）（R-VERIFY-09）
- 候補プールの構築の作業量（組み立て回数など）を計測し、性能の退行を回数で見る（R-VERIFY-10）
- テスト共有の条件セット（総二階・部分二階）を1か所に持つ（R-VERIFY-11）
- 型チェックを含むビルドとテストの両方が通らない状態で、変更を完了としない（R-VERIFY-12）

## 17. 拡張の方針

### 17.1 原則

- 拡張は、生成結果が変わるものなので、GEN_VERSION を上げ、設計相談を経て、別の変更として入れる（R-EXT-01）
- 拡張の優先順は、次の17.2の順とする。外形・方位の拡張（L字・中庭・東西／北道路）は、17.2 の1〜9より先に行わない（R-EXT-02）
- 拡張で足す要件は、この文書に ID 付きで加え、暫定の値は暫定と明記する（R-EXT-03）

### 17.2 品質改善の優先順

1. **部屋種別ごとの最小の短辺をハード制約にする**（7.2）。スコアで調整して残すことはしない
2. **個室にクローゼットを付属させ、余った面積を収納へ回す**（6.3）
3. **廊下と階段の扱いを変える**: 全幅の中廊下をやめ、ホールを最小限にする。リビング階段も選べるようにする。階段は上下同一矩形の通路とし、階段室に開く扉と階段から寝室へのドアを付けない（8.2・8.3）。固定3帯構成（5.3）の変更を伴い、汎用スライシング木が前提になる可能性が高い。浮いた面積は LDK（ダイニングの置ける奥行）と玄関へ戻す
4. **窓の評価を実態に近づける**: 二面採光、通風の対角線、水回り・階段の窓（8.5）
5. **上下階の壁の一致（直下率）を測る**（9章）
6. **家具が置けるかを品質の判定に入れる**: ダイニングテーブル、ベッドが置けない案を落とす／減点する（10.1）
7. **3案の多様性を「考え方の違い」にする**（11章）
8. **敷地を反映する**: 駐車場・庭を配置に反映する。玄関アプローチと道路からの視線を含める（3.2）
9. **洗濯動線を成立させる**（8.6）

### 17.3 その後の拡張候補

- 汎用スライシング木（H/V 再帰分割）。導入時は、木をイミュータブルに扱い、measure のキャッシュが古い値を返さないよう毎回新しく作る
- 外形・方位: L字外形、中庭型、北道路・東西道路
- アイソメ表示
- 好みプリセット（家事動線重視、収納重視 など）
- 3案が揃わない境界条件（0〜2案）の改善

- 汎用スライシング木・L字外形を入れると、固定3帯では隣接しない部屋ペア（浴室と玄関、浴室と LDK など）が隣接しうる。そのときも、ドア除外表（8.2）が正規形で効くことを検査するものとする（R-EXT-04）
