## 0. この文書について

- **R-DOC-01** この文書は、MadoriApp の間取り生成と表示を「どう設計するか／どう設計すべきか」を定める規範文書とする
- **R-DOC-02** 生成される間取りの品質基準、生成ロジックの構造、保存形式の互換性規則は、この文書を正とする
- **R-DOC-03** この文書と `CLAUDE.md` の記述が矛盾するときは、この文書を正として `CLAUDE.md` を直す。この文書にあって実装にないものは、矛盾に含めない

## 1. 目的と対象範囲

### 1.1 目的

- **R-GOAL-01** 一軒家の間取りを3案生成し、施主がアイデア出しに使える図面として比較できるようにする
- **R-GOAL-02** 建築基準法・構造の適合判定は対象外とする

### 1.2 品質目標「それっぽく見える」の定義

- **R-GOAL-03** 「それっぽく見える」とは、住宅の設計を知る人が図面を見て、次のいずれにも嘘がないと感じることとする
  1. 部屋が成立する: 各部屋が、種別ごとの最小の短辺・最小面積を満たし、その用途の家具・設備が収まる
  2. ゾーニングが筋に合う: 南にLDK、北に水回り。水回りがまとまり、玄関から LDK・階段へ迷わず進める
  3. 階が整合する: 上下階で階段が同じ矩形になり、吹抜が LDK の直上に収まり、2階の壁が1階の壁の上に載る
  4. 収納・動線が生活を支える: 個室に収納があり、洗濯や来客の動線が成立する
  5. 図面として読める: 壁・ドア・窓・設備・階段の描き方が建築図面の約束に沿う
  6. 3案が考え方の違いを持つ: 並べたときに、LDK の取り方・階段位置・水回りの配置が違う
- **R-GOAL-04** 見た目で嘘が分かる要素（階段の上下不一致、壁の載らない2階、使えない幅の部屋など）は、「厳密さは対象外」を理由に免除しない

### 1.3 対象範囲

対象とするもの:

- 矩形外形の2階建て（総二階・部分二階）と平屋
- 南道路のみ（道路方位は固定）
- 部屋の寸法・隣接・動線・階の整合・採光・収納の成立
- 条件が成り立たないときの理由と代替案の提示

対象外とするもの:

- **R-SCOPE-01** 厳密な構造計算・建築基準法の適合判定は行わない
- **R-SCOPE-02** 最小寸法を満たさない案を、スコアの調整でごまかして出さない。落とすものはハード制約で落とす
- **R-SCOPE-03** 解説文で実態と違う褒め方をしない（R-TEXT-02）
- **R-SCOPE-04** スコアの絶対値を品質の根拠として主張しない（R-EVAL-11）
- **R-SCOPE-05** 外形・方位の拡張（L字、中庭、東西・北道路）を、品質改善の優先順（R-EXT-05〜R-EXT-13）より先に行わない

### 1.4 優先順位の原則

- **R-GOAL-05** 衝突したときは次の順に優先する
  1. ハード制約（部屋の成立・階の整合・到達可能性）
  2. 再現性（同じ入力 + seed + 版 → 同じ結果）
  3. 品質の物差し（スコア・受け入れ基準）
  4. 案の多様性
  5. 描画の見栄え・補助機能
  - 理由: 成立しない案が多様性やスコアで上位に残ると、品質目標に反する。再現性が崩れるとURL共有・お気に入り・回帰検証が成り立たない

## 2. 用語・単位・座標系

| 用語 | 定義 |
|---|---|
| セル | 1セル = 455mm（半間）。座標・寸法はすべて整数セル |
| 畳 | 1畳 = 8セル² |
| 坪 | 1坪 = 16セル² |
| 芯々 | 壁芯間の寸法。メートル併記は芯々 |
| 短辺 | 矩形の部屋の短い方の辺（セル数） |
| 縦横比 | 長辺 ÷ 短辺 |
| 外形（footprint） | 1階の板（矩形）。幅 W × 高さ H（セル） |
| 帯 | 水平に並ぶ部屋の列。幅方向に部屋が並び、高さは帯で共通 |
| クラスタ | 一体で扱う部屋の組（玄関+土間、キッチン+パントリー、主寝室+WIC など）。テンプレートの単位 |
| ユニット | 並べ替えで崩さないクラスタ（主寝室+WIC、ランドリー+洗面+浴室、LDK+キッチン+パントリー、玄関+土間） |
| アーキタイプ | 帯ごとのクラスタ列を決める間取りの型 |
| 変種 | アーキタイプ内の差（クラスタ列の順序、階段の東西、2階個室の南北配分） |
| 候補プール | seed と無関係に作る全候補 |
| VIA | 通り抜けられる部屋の種別集合。内訳は R-ROOM-05 |
| 居室 | 採光のため外壁に接する必要がある部屋。内訳は R-ROOM-04 |
| 吸収セル | 帯内の余りを受ける部屋 |
| seed | 3案の選抜にだけ使う乱数の種 |
| GEN_VERSION | 生成結果が変わる変更ごとに上げる版番号。基準は R-GEN-10 |
| 下屋 | 部分二階で1階の屋根だけが出る部分 |
| 人気条件 | 延床30坪・2階建て・個室3、延床30坪・平屋・個室3、延床35坪・2階建て・個室4 の3つ |

- **R-UNIT-01** 座標系は、左上を原点、x は東向き、y は南向き（南が道路側）とする
- **R-UNIT-02** 座標は1階を基準とした共通座標とする。2階以上も同じ座標を使う
- **R-UNIT-03** 部屋は軸平行の矩形とし、整数セルの (x, y, w, h) で表す
- **R-UNIT-04** 面積・寸法の判定は常にセル数で行う。メートル・畳は表示用とする
- **R-UNIT-05** 910mm（2セル）寄せはスコアで扱い、座標のスナップはしない

## 4. 生成の全体構成

### 4.1 パイプライン

- **R-GEN-01** 生成は次の段で構成する
  1. 実現可能性判定: 入力が部屋プログラムとして成り立つかを判定する（R-INFEAS-02）
  2. 候補プールの構築（seed 非依存）:
     1. アーキタイプ × 外形候補 × 変種を列挙し、1案ずつ組み立てる
     2. 隣接グラフからドア・窓を自動生成する（派生）
     3. ハード制約で検証し、満たさない候補を棄却する（R-EVAL-01、R-EVAL-14〜R-EVAL-19）
     4. スコアを付ける
     5. 左右反転の重複を除く
  3. seed による選抜: 候補プールから3案を選ぶ（R-SEL-02）
  4. 付加情報の生成: 名前・タグ・解説文（R-TEXT-01）
- **R-GEN-02** 候補プールは、seed と無関係に全候補を作る
  - 理由: seed を選抜だけに使うことで、候補の全体像（ギャラリー・件数）が seed に依存せず、再現性と説明可能性が保てる
- **R-GEN-03** 候補プールは条件ごとにメモ化してよい。メモ化の有無で結果を変えない
- **R-GEN-04** 診断用の生成（キャッシュに入れない版）は、通常の生成と同じ結果を返す

### 4.2 決定性

- **R-GEN-05** 乱数は seed 付きの決定的な乱数だけを使う。`Math.random` や時刻を生成に使わない
- **R-GEN-06** 同じ入力 + seed + GEN_VERSION からは、案の集合・順序・各案の内容がビット単位で同じになるとする
- **R-GEN-07** 生成ロジック（`src/core/`）はフレームワーク非依存の純 TypeScript とし、React・DOM・ブラウザ API に依存しない。Node 上でそのまま動く状態を保つ
- **R-GEN-08** 帯・セルなどの入力データは破壊的に変更しない。作業用データは関数内で新しく作る
- **R-GEN-09** 並びに曖昧さがある箇所（同点のタイブレークなど）は、決定的な順序を定める

### 4.3 GEN_VERSION の意味

- **R-GEN-10** GEN_VERSION は、golden fixture に含まれる出力（案・スコア・名前・タグ。候補プールの件数・ハッシュと実現可能性判定の結果を含む）が変わる変更を入れるたびに上げる
  - 版を上げる例: アルゴリズム・配分・順序・ハード制約・スコアの式／重み・多様性選抜の規則・変種の列挙の変更
  - 版を上げない例: 描画のみの変更、UI、解説文、性能改善（出力が同一のもの）
- **R-GEN-11** 版を上げたときの扱いは、R-COMPAT-16 に従う
- **R-GEN-12** 生成結果が変わる変更は、機能追加のついでに入れず、別の変更として扱う

## 5. 空間構成

### 5.1 抽象要件（方式に依らない）

- **R-SPACE-01** 各階は、板（矩形）を隙間なく部屋の矩形で埋める
- **R-SPACE-02** 各部屋は軸平行の矩形とし、隣接は辺の共有で定義する。隣接グラフからドア・窓を導出する
- **R-SPACE-03** すべての部屋は、玄関から、ドアでつながる経路で到達できるとする
- **R-SPACE-04** 廊下・ホールは最小限とする。全幅の中廊下を毎階強制する構成は採らない
  - 現行方式（固定3帯）は部分適合: ホール帯の端を隣の部屋が吸収する（R-SPACE-34）が、2階には全幅のホールが残る案がある。完全な適合は汎用スライシング木（R-EXT-07）
- **R-SPACE-34** ［現行方式］ホール帯の端は、隣の帯の部屋が高さ +2 で吸収してよい。割り付けの後・収納化（R-PROG-13）の前に、階ごとに、西端 → 東端の順で、切り取りが長い候補から試す。吸収できる種別は LDK・主寝室・洋室・書斎・和室・玄関・土間・キッチン・WIC・パントリー・収納・クローゼット（クローゼットは高さ +2 しても 8 以下のとき）で、水回り・階段・吹抜は吸収しない。吸収の後の階が、ハード制約（R-SPACE-03、R-ROOM-03、R-FLOW-05 ほか）・付属収納の持ち主との辺の共有・階段の口の全幅（R-STAIR-07）・ホールの長さ 4 セル以上を満たすときだけ採る。玄関・土間は、最大面積を超えないときだけ吸収する［暫定］。吸収で個室収納（個室にドアでつながる 2×4 セル以上のクローゼット・WIC・持ち主のある収納）が減る場合は、その吸収を採らない（`keepStorage`。吸収が収納化（R-PROG-13）より先に端を取って、個室のクローゼットを奪うのを防ぐ）［暫定］
- **R-SPACE-05** 部屋の幅・高さの配分は、各部屋の最小面積・最大面積・最小の短辺の範囲に収めたうえで、目標面積に近づける
- **R-SPACE-06** 余りが出たときの配分は、R-PROG-11 に従う

### 5.2 外形の規則

- **R-SPACE-07** 外形は、延床面積に見合う整数セルの矩形とし、候補を決定的な順で複数挙げる。総二階・平屋の候補数の上限は10とする
- **R-SPACE-28** 外形の W・H は 12〜30、W/H は 0.62〜1.62 の範囲に限る
- **R-SPACE-29** 部分二階の外形の組は、形（東西下屋・南下屋）ごとに上位6件を決定的な順で挙げ、最大12件とする
- **R-SPACE-08** 外形は矩形のみとする。L字・中庭型は拡張（R-EXT-14）で扱う
- **R-SPACE-09** 道路は南とし、方位は固定する

### 5.3 現行方式: 固定3帯構成

抽象要件の実現方式として、次を採る。方式を変えるときは GEN_VERSION を上げる（R-GEN-10）。

- **R-SPACE-10** ［現行方式］この要件は現行方式に限る。各階を北帯 / ホール帯 / 南帯の3本の水平帯で構成する
- **R-SPACE-11** ［現行方式］1階の階段は北帯、LDK は南帯に置く
- **R-SPACE-12** ［現行方式］アーキタイプが帯ごとのクラスタ列を決める。数は、2階建て3個、平屋2個とする
- **R-SPACE-13** ［現行方式］帯の高さと帯内の幅は、clamp 付き water-filling（二分探索）+ 最大剰余法で配分する
- **R-SPACE-14** ［現行方式］帯内の余りは吸収セルへ入れる。溢れたときは、結合できるクラスタ（玄関+土間 → キッチン+パントリー）を順に結合して再試行する
- **R-SPACE-15** ［現行方式］変種は、クラスタ列の順序（ユニットを崩さない並べ替え）、階段の東西、2階個室の南北配分で作る。適用後の帯構成が同一の変種は、列挙前に省く
- **R-SPACE-16** ［現行方式］帯の高さを seed で揺らす案は採らない
  - 理由: 重複が増えるだけで、吹抜の整合違反が増える
- **R-SPACE-05 の実現**［現行方式］割り付けは、帯内の幅の下限に最小の短辺（R-ROOM-03）を使い、帯の高さの下限も帯内の短辺の最大以上に引き上げる。割り付けた後の検証（validate）は安全網とする
- 注記: この方式は汎用のスライシング木（H/V 再帰分割）を持たない。リビング階段・中廊下なしの構成は、スライシング木が前提になる可能性が高い（R-EXT-07）

### 5.4 部分二階の幾何規則

- **R-SPACE-17** 部分二階は、2階を1階より小さくし、1階の屋根（下屋）が出る形とする。2階建てのときだけ選べる
- **R-SPACE-18** 2階の板は1階の板に内包される
- **R-SPACE-19** ［現行方式］2階の板は北寄せ（y 方向の位置 0）とし、階段側寄せとする。階段が東端なら 2階の x 位置は W1−W2、西端なら 0とする
  - 理由: 階段が北帯の y=0 にあるため
- **R-SPACE-20** 1階との関係は、一辺共有の2形のみとする。直積（東西かつ南）は認めない
- **R-SPACE-31** 東西下屋は、H2 = H1、W2 = W1−k（k ≥ 3、W2 ≥ 9）とし、下屋は階段と反対側に置く。下屋の出 k は3セル（1.365m）以上とする
- **R-SPACE-32** 南下屋は、W2 = W1、H2 = H1−k（k ≥ 3、H2 ≥ 13）とする
- **R-SPACE-21** 2階の面積割合 W2×H2 ÷ 延床は 0.35〜0.45 とする
- **R-SPACE-22** 部分二階の実現可能性の下限は、「2階の最低面積の合計 × 1.18 ≤ 延床 × 0.45」とする
- **R-SPACE-23** 各階の板は、階ごとの矩形で表す
- **R-SPACE-33** 外壁の判定（採光・窓・外壁描画・解説の階段側）は、その階の矩形を使う
- **R-SPACE-24** LDK は1階にある前提とし、LDK に関する判定（名前の「南LDK」、解説の LDK 南判定）は1階の板で行う
- **R-SPACE-25** 延床面積は各階の板面積の合計とする。総二階では「1階の板面積 × 階数」と一致する
- **R-SPACE-26** 壁の直下率（2階の壁が1階の壁の上に載る割合）は、部分二階だけでなく全体で扱う（R-IDX-05）
- **R-SPACE-27** 部分二階 + 吹き抜けが成り立たないときは、理由と代替案を出す（R-INFEAS-03）
  - 理由: 2階南帯が低くなり、吹抜と相性が悪い

### 6.1 部屋リストの作り方

- **R-PROG-01** 部屋リストは、入力から決定的に作る。基本の部屋は、LDK、玄関、階段（2階建て）、ホール、水回り（浴室・洗面・トイレ）、主寝室、洋室（個室数に応じて）とする

- **R-PROG-03** テンプレートは、部屋単位ではなくクラスタ単位とする
- **R-PROG-04** ［現行方式］水回りユニットは、ランドリー → 洗面 → 浴室 の順に並べる
  - 理由: 水回りの隣接制約（R-WET-01）を、並べ方だけで満たすため

### 6.2 階への配置

- **R-PROG-06** 平屋は、すべてを1階に置く
- **R-PROG-07** 2階建ては、LDK・玄関・水回り・階段を1階、主寝室・洋室を主に2階に置く。個室の階への配分は、個室数と延床から決める
- **R-PROG-08** トイレは、階ごとの水回り隣接（R-WET-01）を満たす階に置く
- **R-PROG-09** 階段は、1階と2階で同じ矩形で置く（R-STAIR-01）
- **R-PROG-10** 2階の個室は、南北に配分する。変種の1つとして扱う

### 6.3 余剰面積の配分の優先順位

- **R-PROG-11** ［暫定］帯・階に余りが出たときは、次の順で配分する
  1. 各部屋の最小面積・最小の短辺を満たす（満たせない案は棄却）
  2. 個室に付属するクローゼット（幅2セル、長さ4〜8セル）。割り付けのとき個室の矩形から切り出す（GEN_VERSION 5。付ける方式は R-VERIFY-13 の暫定形）
  3. 追加の面積を使わない収納化: 持ち主のない収納を個室のクローゼットに付け替える → ホール帯の行き止まりをクローゼットにする → 最大面積を超えた水回りの外壁側2列を収納にする
  4. 吸収セルへの配分: LDK → 個室 → 収納系 → 玄関 → キッチン → 水回り（水回りを後ろへ回し、洗面・浴室・トイレに余りを吸わせにくくする。R-PROG-12）
  - 玄関収納（下駄箱）・階段下の収納・玄関の標準4セル幅への拡大は、固定3帯では作れない（R-EXT-07）
- **R-PROG-12** 洗面や廊下に余りを吸収させない。吸収させるときは、最大面積の範囲内に限る
- **R-PROG-13** 収納は、独立した部屋としてだけではなく、部屋に付属する形で発生させる
- **R-PROG-14** ［暫定］R-PROG-11 の順序は、測定と相談を経て確定または改訂する
- **R-PROG-15** ［未確定］配分の細則（各項への配分量）は、数値を置かない

## 8. 部屋どうしの関係

### 8.1 水回りの隣接（ハード制約）

- **R-WET-01** 水回りは、階ごとに次を満たす。「隣接」は辺を2セル以上共有することとする
  - 浴室 → 洗面と隣接
  - ランドリー → 洗面と隣接
  - トイレ → 同じ階の浴室・洗面・ランドリーのいずれかと隣接
- **R-WET-02** キッチン・パントリーは、R-WET-01 の対象外とする
- **R-WET-03** 水回りの集約（全体としてまとまること）は、緩い評価としてスコアで扱う（R-EVAL-07）

### 8.2 ドアの規則

- **R-DOOR-01** ドアは隣接グラフから自動生成することとする。経由可能性は部屋種別ごとの VIA（R-ROOM-05）で判定する。階段の出入りは、扉でなく開口（R-DOOR-14）として生成する
- **R-DOOR-02** 浴室のドアは洗面とだけ付ける
- **R-DOOR-03** 階段とトイレの間にドアを付けない

階段とドアの関係は、次の3つで決める。

- **R-DOOR-14** 階段は VIA（通り抜け可）とする。階段の出入りは、扉のない開口とする。開口でつなぐ相手は、ホール・玄関・土間・LDK だけとする。開口は葉も弧も持たず、通行点は共有区間の中点とする
- **R-DOOR-04** 階段室に開く扉は付けない
  - 理由: 転落防止
- **R-DOOR-13** 階段から居室へ直接入る扉は付けない
- **R-DOOR-05** ドア除外表は部屋種別のペア配列とし、ペアを名前順に正規化した集合で照合する。手書きの文字列キーを使わない
  - 理由: 正規形と一致しないキーでは除外が効かなくなる
- **R-DOOR-06** ドアの形状（葉の位置・長さ・開き先・弧）は1か所で算出し、描画・家具配置・動線計算が同じ結果を共有する
- **R-DOOR-07** 葉は共有区間内に置く。最大長は1.8セル（約0.82m）とし、共有区間の34%地点を中心にクランプする
- **R-DOOR-08** 弧の半径は、葉の長さと開き先の深さの小さい方とし、弧の矩形は開き先の部屋に収める
- **R-DOOR-09** 開き先は、片方だけ VIA でない場合はその部屋、同条件なら面積の小さい方とする
- **R-DOOR-15** VIA どうしのタイブレークは、面積 → y → x の順とする
- **R-DOOR-10** 同じ部屋に開く弧の矩形が重なるときは、葉を共有区間の端へ寄せる → 開き先を反対の部屋に切り替える、の順で避ける。避けられなければ既定の形のままとする
- **R-DOOR-11** 玄関の外開きは、半径を玄関の幅以下とする
- **R-DOOR-12** トイレ・キッチンでは、器具と弧が重ならないことが望ましい
- **R-DOOR-16** ［未確定］トイレの外開きの特例は、採るかどうかを決めていない

### 8.3 階段

- **R-STAIR-01** 階段は、上下階で同じ矩形・同じ上り口／下り口とする（x・y・幅・高さが一致）。GEN_VERSION 6 で適合（R-STAIR-08）
  - 理由: 上下で形の違う階段は、見た目で嘘が分かる。階段の高さ（y）を階ごとの帯の高さに依存させない
- **R-STAIR-02** 階段は、段数・踏面・蹴上げの幾何を持つ。矩形がその幾何を収められることを成立条件とする
  - 例: 14段上がりの直階段は、踏面13枚 × 22cm ≒ 2.9m の長さが必要。奥行 1.82m の矩形では直階段は成立しない
- **R-STAIR-03** ［暫定］階段の幾何の数値（蹴上げ・踏面・段数）は、R-STAIR-02 の例の寸法関係を満たす範囲に限る。前提は 階高 約2.9m・14段上がり（蹴上げ 約207mm）・踏面 約227mm（= 1.365m ÷ 6）。矩形の判定は、セル数で行う（R-UNIT-04）

  | 形式 | 矩形（短辺×長辺、セル） | 成り立ち | GEN_VERSION 6 |
  |---|---|---|---|
  | 折り返し（踊り場付き）・最小 | 4×5 | 幅0.91mの2列。各列 3セル（1.365m）に6段、奥 2セルが踊り場。7段＋7段＝14段 | 採用 |
  | 折り返し・標準 | 4×6 | 4×5 に、口の側の1セルの溜まり（上り口の手前）を足したもの | 採用 |
  | 直進・最小 | 2×7 | 踏面13枚 × 227mm ≒ 2.95m | 採用しない（R-STAIR-06 とあわせて R-EXT-07） |
  | 1.82m 四方 | 4×4 | 折り返しの踊り場が入らない（3+2=5 セルが要る）。回り階段（踏面が扇形）は範囲外 | 不可（棄却） |
- **R-STAIR-04** 階段の描画は、段と上り方向の矢印を持つ（R-DRAW-07）
- **R-STAIR-07** 折り返し階段の口の辺（上り口と下り口が並ぶ短辺）は、両階で、開口でつながる部屋（ホール・玄関・土間・LDK）に全幅（4セル）で接する。現行方式（固定3帯）では口の辺は南（ホール帯側）で、ホール帯の端の吸収・行き止まりの収納化（R-SPACE-34、R-PROG-13）は、ホール1室が口の辺の全幅を覆うことを保つ［暫定］
- **R-STAIR-08** ［現行方式］2階建ての北帯（階段のある帯）の高さ hN は両階で共通とし、変種の軸として 5・6 を列挙する。階段は 4×hN になり、組み立て時に x・y・幅・高さの一致を検査する。平屋は階段がないので振らない。部分二階の成立条件は、仕様の見込み（減らない）に反して 48 → 44 に減った（24坪/個室2/こだわりなし・吹抜、28坪/個室2・3/ランドリー+パントリー+WIC。v5 の提示案の 1F の階段が 4×4 だけで、v6 では成立しないため）
- **R-STAIR-06** リビング階段は選べるようにする（R-EXT-07）
- **R-STAIR-05** 階段の矩形が不足するとき、1F・2F の座標一致を崩して通すことはしない。通せない条件は棄却し、診断で案内する（R-INFEAS-03）

### 8.4 吹抜

- **R-VOID-01** 吹抜は、LDK の直上に収まる。x・y ともに LDK の矩形内とする
- **R-VOID-02** ［現行方式］吹抜ありのときは、2階南帯の高さを1階南帯の高さ以下に抑える
- **R-VOID-03** ［現行方式］部分二階では、2階南帯の高さの上限を（1階南帯の高さ − (H1 − H2)）とする
- **R-VOID-04** 吹抜と階段の間にドアを付けない
- **R-VOID-05** 吹抜は組み立て時に検査し、満たさない候補は棄却する

### 8.5 窓

- **R-WIN-01** 窓は、外壁に接する辺から自動生成する
- **R-WIN-02** 角部屋は二面採光を基本とする
- **R-WIN-03** 通風を、対角の開口の経路として評価する
- **R-WIN-04** 水回り・階段・廊下の窓も評価対象とする
- **R-WIN-05** 道路側（南）からの視線を考慮し、LDK の大窓が道路から丸見えにならないようにすることが望ましい
- **R-WIN-06** ［未確定］窓の評価は、スコア項目「採光」（R-EVAL-07）の拡張として扱う。評価式は置かない

### 8.6 動線

- **R-FLOW-01** 動線は、ドアでつながる部屋の最短経路で計算する
  - 来客: 玄関 → LDK
  - 生活: LDK → 洗面・浴室
- **R-FLOW-02** 中継は VIA の部屋を優先する。VIA だけで届かないときに限り、VIA 以外の部屋を通すことを、ペナルティを課したうえで認める
- **R-FLOW-03** 階をまたぐ区間は、階段までを描く
- **R-FLOW-05** 動線のガードはハード制約とする。G1: トイレは、ホール・玄関・土間のいずれかとドア・開口でつながる。G2: 洗面は、ホール・玄関・土間・LDK のいずれかとつながる（個室経由は不可）。G3: 主寝室・洋室は、ホール・玄関・土間のいずれかとドア・開口でつながる（LDK 経由は不可）。書斎・和室は、ホール・玄関・土間・LDK のいずれかとつながる（WIC・他の個室を通らないと入れない個室は不可）。G4: 階段と玄関のある階（2階建ての1F）では、玄関（なければ土間）が階段と直接つながるか、玄関・ホール・階段がつながる（LDK を通らずに階段へ行ける）。リビング階段は R-STAIR-06 で別の型として選べるようにする
- **R-FLOW-04** 洗濯動線は、洗う → 干す → しまうの置き場（バルコニー、室内干し、ランドリー、クローゼット）が用意されていることで成立とする

## 9. 全体の指標

| 指標 | 定義 | 目標 |
|---|---|---|
| 廊下率 | ホール面積 ÷ 延床 | 5〜8%（R-IDX-01） |
| 収納率 | 収納面積（付属のクローゼット・WIC・収納・パントリー・玄関収納を含む）÷ 延床 | 10%以上（R-IDX-02） |
| LDK のダイニング | 家具配置でダイニングテーブルが置けること | 必須（R-IDX-03） |
| 面積配分 | 各部屋の面積が目標に対して妥当か。上下階の配分を含む | R-IDX-04 |
| 直下率 | 2階の間仕切りのうち、1階の壁の上に載る割合 | R-IDX-05 |

- **R-IDX-01** 廊下率の目標は 5〜8% とする。現行方式（固定3帯）は部分適合（R-SPACE-04）
- **R-IDX-02** 収納率の目標は 10%以上とする。R-ROOM-03 の最小の短辺を満たさないもの（例: 幅2セルのWIC）は、収納面積に数えない
- **R-IDX-03** LDK は、家具配置でダイニングテーブルが置けることとする。対面キッチンなら、カップボード 0.65m + 通路 0.9m + カウンター 0.65m = 2.2m に加え、ダイニングテーブルが置ける奥行を確保する
- **R-IDX-04** ［未確定］面積配分は、水回りが肥大せず、個室が最小面積付近に偏らないことを方針とする。数値は置かない
- **R-IDX-05** ［未確定］直下率の目標値は置かない。測定結果をもとに値を決める
- **R-IDX-09** 直下率は、2階の間仕切り（その階の板の外周以外の、部屋の辺。吹抜の辺は数えない）を単位長の壁片に分け、1階の壁（部屋の辺。外周を含む）の真上にある壁片の割合で測る
- **R-IDX-06** 廊下率の目標は設計の方向であり、ハード制約にしない。スコアでは 8% 以下を満点・14% を 0 点とする折れ線で評価し（R-EVAL-22）、目標より緩い範囲を許す（R-EVAL-07）
- **R-IDX-07** 面積配分は、ハード制約の最小面積・最大面積に加えて、スコアの面積適合（R-EVAL-07）で評価する
- **R-IDX-08** 解説文も、R-IDX-02 と同じ基準で収納を数える（R-TEXT-02）

## 10. 制約の層と評価モデル

### 10.1 3つの層

| 層 | 性格 | 違反したとき |
|---|---|---|
| ハード制約 | 成立の条件 | 候補を棄却する。スコアで補わない |
| ソフトスコア | 順位付けの物差し | 点が下がる |
| 受け入れ基準 | 人の目での確認 | 変更を入れない／直す |

ハード制約:

- **R-EVAL-01** 全室への到達可能性を満たす。通り抜け可否は部屋種別ごとの VIA（R-ROOM-05）で判定する
- **R-EVAL-14** 居室は外壁に接する（採光。R-ROOM-04）
- **R-EVAL-15** 各部屋は最低面積（R-ROOM-01 の表の最小）を満たす
- **R-EVAL-16** 各部屋は最小の短辺（R-ROOM-03）を満たす
- **R-EVAL-17** 水回りの隣接（R-WET-01）を満たす
- **R-EVAL-18** 階段が上下で一致する（R-STAIR-01）
- **R-EVAL-19** 吹抜が LDK 直上に収まる（R-VOID-01）
- **R-EVAL-20** 階ごとの検証は、その階の板（R-SPACE-23）に対して行う

その他の層:

- **R-EVAL-02** ソフトスコアは、R-EVAL-07 の8項目（GEN_VERSION 5 で「個室収納」を追加）と、R-EVAL-13 で加える項目とする
- **R-EVAL-03** 受け入れ基準は、R-VERIFY-13〜R-VERIFY-18 の6問とする
- **R-EVAL-04** ［未確定］「家具が置けるか」（ダイニングテーブル・ベッド）を、ハード制約とするか減点とするかは決めていない。決定までは受け入れ基準に置く。決定は設計相談で行う
- **R-EVAL-05** 振り分けの原則は、落とすべきもの（成立しない寸法・階の不整合）はハード制約、程度の差を見るものはソフトスコア、人の判断が要るものは受け入れ基準とする
- **R-EVAL-06** 最小の短辺のハード制約により0案になる条件は、成立しない案を出していた条件として扱い、診断と代替案で案内する（R-INFEAS-03）
- **R-EVAL-24** 人気条件では、すべてのハード制約を課したうえで3案を維持する。維持できないときは、条件側の扱いを含めて設計相談で決める

### 10.2 ソフトスコアの項目と重み

- **R-EVAL-07** 総合点は、次の表の項目点（0〜1）の重み付き和 × 100 を四捨五入した整数とする
- **R-EVAL-08** ［暫定］重みは、表の値とする

| 項目 | 重み | 意味 |
|---|---|---|
| 採光 | 0.18 | 居室のうち外壁に接する割合 |
| 面積適合 | 0.18 | 部屋面積 ÷ 目標面積（0.4〜1.8 にクランプ）が 1 に近いほど高い。ホール・吹抜・階段・付属収納（クローゼットなど `of` を持つ部屋）は除く |
| 縦横比 | 0.135 | 部屋ごとに 1 − (比 − 1) ÷ 3 を 0〜1 にクランプ（比 4.0 で 0 点）。ホール・吹抜・階段・付属収納は除く |
| 廊下の少なさ | 0.135 | (0.14 − ホール面積 ÷ 延床) ÷ (0.14 − 0.08) を 0〜1 にクランプ（8% 以下で満点、14% で 0 点。GEN_VERSION 6 で変更） |
| 動線・ドア | 0.135 | ドア数（階段の開口も数える）÷ (部屋数 × 0.62) を 0〜1 にクランプ |
| 水回り集約 | 0.09 | 水回りの中心の重心からの平均距離 ÷ (W × 0.55) が小さいほど高い。水回りが2室未満なら 1 |
| 910モジュール | 0.045 | x と w がともに偶数の部屋の割合 |
| 個室収納 | 0.10 | 主寝室・洋室のうち、ドアでつながる 2×4 セル以上のクローゼット・WIC・持ち主のある収納を持つ部屋の割合。個室がなければ 1（GEN_VERSION 5 で追加。既存7項目は従来の ×0.9） |

- **R-EVAL-09** 重みの合計は 1.00 とする
- **R-EVAL-22** ［暫定］式中の定数（0.08、0.14、0.62、0.55、0.4〜1.8、3）は、表の値とする

### 10.3 スコアは順位付け専用

- **R-EVAL-10** スコアは、候補の順位付けと選抜（R-SEL-02）にだけ使う
- **R-EVAL-11** スコアの絶対値を、品質の根拠として UI・解説文・文書で主張しない
  - 理由: スコアは、部屋の短辺・家具・収納などの成立を測る物差しではない（R-EVAL-13）。成立の保証は、ハード制約と受け入れ基準が担う
- **R-EVAL-12** UI に点数を出すときは、順位の参考であることが分かる扱いとする

### 10.4 スコアに加えるべき観測項目

- **R-EVAL-13** ［未確定］次の項目を観測できるようにする。項目を加えるときは、重みを再設計し、GEN_VERSION を上げる（R-GEN-10）。重み・式は置かない
  - 部屋の短辺の絶対寸法（面積適合は形を見ず、縦横比は相対比しか見ない）
  - 家具が置けるか（ダイニング・ベッド）
  - （個室の収納の有無は GEN_VERSION 5 でスコア項目「個室収納」（R-EVAL-07）として実装済み）
  - 二面採光と通風
  - 上下の壁の一致（直下率）
  - 階段の成立（幾何）
  - 道路からの視線（プライバシー）
  - 洗濯動線
  - 上下階の面積配分の妥当性（巨大な洗面と小さな個室が同居しない）

## 11. 3案の選び方と多様性

- **R-SEL-01** 候補プールの各案は、スコア降順に並べる（左右反転の重複は除く）
- **R-SEL-02** ［暫定］選抜は seed を使って3案を選ぶ。対象は、最良スコアから 8 点以内の窓に入る候補とする
- **R-SEL-09** ［暫定］窓の中から、温度 2 の Gumbel-top-k 抽選で選ぶ
- **R-SEL-10** ［暫定］すでに選んだ案との多様性（距離）が 0.16 以上のものだけを採る
- **R-SEL-03** 窓幅・温度・しきい値（R-SEL-02、R-SEL-09、R-SEL-10）は、測定と相談を経て確定または改訂する
- **R-SEL-04** seed は選抜にだけ使う。seed を進めると3案の組が変わることが望ましい。出せる案が尽きたら、その旨を表示する
- **R-SEL-05** 多様性は、「考え方の違い」で測る。LDK の取り方・階段位置・水回りの配置が違う案を出す。北帯の順番と階段の東西だけが違う案は、実質同一案として扱う
- **R-SEL-12** ［未確定］多様性の距離の定義（どの特徴をどう重み付けるか）は、R-SEL-05 に沿って設計し直す。具体の式は置かない
- **R-SEL-06** 3案が揃わないときは、揃った数を出し、理由を示す（R-INFEAS-03）
- **R-SEL-07** ギャラリー（候補の一覧）は、候補プールから多様性を優先して選んだ上位24案を、全N案の件数つきで出す
- **R-SEL-13** ギャラリーの選び方（最遠点選択）には、スコアの下限または重み付けを入れることが望ましい
- **R-SEL-08** 「別の3案」の履歴は上限20組とし、URL ハッシュには入れない

## 12. 名前・タグ・解説文の原則

- **R-TEXT-01** 名前・特徴タグは、案の配置と入力から決定的に作る
- **R-TEXT-02** 名前・タグ・解説文は、図面に実際に当てはまる特徴だけを書く。当てはまらない特徴・実態と違う褒め方は書かない
  - 例: 使えない幅の帯を数えて「収納が多め」と書かない
- **R-TEXT-03** 解説文は、スコアの内訳・配置・入力だけから作る純関数とし、2〜3文とする。部分二階は先頭に1文足し、最大4文とする
- **R-TEXT-04** 弱点（廊下が長い・縦横比・面積適合・クローゼットのない個室）がある案は、必ず触れる。文数が足りなければ、階段の文と1文にまとめる
- **R-TEXT-05** 階段と個室の関係は階ごとに判定し、個室には書斎・和室を含む
- **R-TEXT-06** LDK の畳数は、キッチンが独立の案ではキッチンを含める
- **R-TEXT-07** 割合は小数1桁に切り捨てて書く
- **R-TEXT-08** 解説文の言い回し・しきい値は、1か所の定義にまとめる
- **R-TEXT-09** 文を足すときは、「当てはまる場合だけ書く」条件を先に定める

## 13. 成り立たない条件の扱い

- **R-INFEAS-01** 無理な条件（例: 20坪 + 個室5、平屋 + 吹き抜け）は、黙って要素を落とさない。理由と代替案を UI に出す
- **R-INFEAS-02** 実現可能性判定は、部屋プログラムが入力の延床・階数・個室数・こだわりに対して成り立つかを調べる
- **R-INFEAS-10** 部分二階の実現可能性判定は、R-SPACE-22 の下限を使う
- **R-INFEAS-03** 実現可能でも、生成が0案・3案未満になる条件では、どの階が崩れたかの理由と、代替案を出す
- **R-INFEAS-04** 代替案は、実際に3案を返すことを確かめたものだけを、最大3件出す
- **R-INFEAS-05** 部分二階で成り立たないときは、代替の先頭を「総二階にする」とする
- **R-INFEAS-06** 吹抜が成り立たないときは「吹抜を外す」を代替に含める
- **R-INFEAS-07** 「おまかせ条件」は、実現可能で、かつ3案が返る条件だけを返す
- **R-INFEAS-08** ハード制約（特に最小の短辺）により成り立たない条件は、診断と代替案の対象とする（R-INFEAS-03）。人気条件は R-EVAL-24 に従う
- **R-INFEAS-09** 成り立ちにくい境界条件（0〜2案になる条件）は、診断で案内するだけでなく、生成側の改善（R-EXT-15）で減らす方向とする

## 14. 描画の仕様

- **R-DRAW-01** 描画品質は生成と同じくらい重要とする
- **R-DRAW-02** 図面は SVG で描く。画面・印刷・PNG 書き出しは同じ SVG を使う
- **R-DRAW-03** 壁は、外壁と間仕切りで太さを描き分ける

## 15. 保存と互換性

### 15.1 URL ハッシュ

- **R-COMPAT-01** 入力 + seed + GEN_VERSION を URL ハッシュ（`c`）に保存する
- **R-COMPAT-02** 開いている1案は planKey を `p` で保存する
- **R-COMPAT-03** 総二階・平屋のハッシュ文字列には `story` を含めない。`story` は、部分二階かつ2階建てのときだけ出力する
- **R-COMPAT-04** 解釈（parse）は、`story` が部分二階を表す値のときだけ採用し、それ以外は総二階として扱う
- **R-COMPAT-05** 古い版（v1）のリンクは、警告を出して新しいロジックで開き、`p` は捨てる

### 15.2 planKey

- **R-COMPAT-06** planKey の形式は `アーキタイプ-幅x高さ-変種`（例: `1-16x14-E01000`）とする。部分二階は末尾に `-p<W2>x<H2>` を付ける。クローゼットを必ず付ける強モードの案だけ、さらに末尾に `-k` を付ける（例: `1-16x14-E01000-k`）
- **R-COMPAT-07** v1 の形式は `アーキタイプ-幅x高さ`（変種なし）とする。v1 の key からの再構築は行わない
- **R-COMPAT-08** planKey から案を再構築できる。再構築結果は、同じ版の生成結果と一致する

### 15.3 お気に入り

- **R-COMPAT-09** お気に入りは、案のデータそのものをブラウザに保存する
- **R-COMPAT-18** お気に入りの上限は30件とする
- **R-COMPAT-10** 保存形式・上限・壊れたデータの復旧は、1か所で定義する
- **R-COMPAT-19** ストレージへの入出力は、関数を引数で受ける形にし、テストで差し替えられるようにする
- **R-COMPAT-11** 読み込み時に、案データが建物に収まる正の矩形などの整合を検査し、壊れたデータは取り除く
- **R-COMPAT-12** 旧版のお気に入りは、「旧バージョン」バッジ付きで表示する
- **R-COMPAT-13** 保存データの識別子（条件 ID）は、部分二階のときだけ部分二階を示す印を足し、総二階・平屋の識別子には足さない

### 15.4 データ形式の互換規則

- **R-COMPAT-14** 総二階では、階ごとの板（`fp`）を持たない。付けると、正準ハッシュと golden が変わる
- **R-COMPAT-15** 既存データの型に項目を足すときは、任意項目とし、なければ従来の意味で読む

### 15.5 版を上げたときの扱い

- **R-COMPAT-16** GEN_VERSION を上げたら、版別の golden fixture を新しい版で書き出す（R-VERIFY-02）。旧版のリンクは R-COMPAT-05、旧版のお気に入りは R-COMPAT-12 に従う
- **R-COMPAT-20** 旧版の fixture は、版の移行検証用に残してよい
- **R-COMPAT-17** 旧版の挙動を新版で再現することは求めない。旧版の案は、保存データから表示できればよい

## 16. 検証の方法

### 16.1 golden の考え方

- **R-VERIFY-01** golden は2本立てとする
  - v1 の正解は `legacy/index.html`。名前・タグ・実現可能性判定を、原型を実行して比較する。生成そのものは、方式が変わった版では比較しない
  - 版別の出力は `__fixtures__/gen-v<GEN_VERSION>.json`。生成案（複数条件 × 複数 seed）、候補プールの件数・上位10件・ハッシュ、実現可能性判定のグリッドの3案を固定する
- **R-VERIFY-19** 部分二階は、別の fixture を持つ
- **R-VERIFY-02** R-GEN-10 に当たる変更を入れるときは、GEN_VERSION を上げたうえで、fixture を書き出す
- **R-VERIFY-20** 版が同じまま fixture の中身だけが変わる更新は、拒否する。強制するときだけ、明示の指定を要する
- **R-VERIFY-03** fixture の更新は、生成結果が変わったことを意図した差分として確認できる形で行う
- **R-VERIFY-04** `legacy/` は削除・改変しない

### 16.2 受け入れ基準＝施主の視点の6問

- **R-VERIFY-05** 生成の変更を入れたら、R-VERIFY-13〜R-VERIFY-18 の6問に、図の上で答えられることを確認する。答えられない案が出るなら、変更は未完了とする
- **R-VERIFY-13** ［暫定］問1（収納）: すべての個室（主寝室・洋室）に、2×4セル以上のクローゼットまたは WIC が付属していることが、図で確認できる。付かない個室がある案は、解説文の弱点で「クローゼットのない個室があること」と明示する（GEN_VERSION 5 の暫定形。全個室への付属は、強モードの案（planKey の末尾 `-k`）では保証されるが、提示案では人気条件で、v5 は約6割、GEN_VERSION 6 は 48.1%（個室への付属率 74.9%）にとどまる。v6 で下がったのは、階段を 4×5/4×6 にそろえて北帯の高さを 5・6 に固定したため。完全な適合は R-EXT-07）
- **R-VERIFY-14** 問2（玄関）: 玄関の短辺が 3 セル以上で、下駄箱（幅2セル程度）を置ける壁面が、ドアに邪魔されずに残っている
- **R-VERIFY-15** 問3（ダイニング）: LDK の家具配置で、ダイニングテーブルの置き場が図で指せる（R-IDX-03）
- **R-VERIFY-16** 問4（洗濯）: 洗う・干す・しまうの置き場が、それぞれ図で指せる（R-FLOW-04）
- **R-VERIFY-17** 問5（面積配分）: 浴室・洗面・トイレ・ランドリーが、それぞれ最大面積以下で、個室の面積が最小面積付近に偏っていない（R-IDX-04）
- **R-VERIFY-18** 問6（3案の違い）: 3案のどの2案も、LDK の取り方・階段位置・水回りの配置のうち少なくとも1つが違う。北帯の順番と階段の東西だけの違いは、違いに数えない（R-SEL-05）

### 16.3 テストの最低限

- **R-VERIFY-06** 人気条件で、複数の seed で3案が出る
- **R-VERIFY-07** 生成した案が、ハード制約を満たす
- **R-VERIFY-08** 同じ seed + 入力で、同じ結果になる（再現性）
- **R-VERIFY-09** ハード制約の検証は、生成側の検証とは別の独立した実装でも行う（クラスタの辺共有・階段の x 一致・吹抜 ⊂ LDK を含む）
- **R-VERIFY-10** 候補プールの構築の作業量（組み立て回数など）を計測し、性能の退行を回数で見る
- **R-VERIFY-11** テスト共有の条件セット（総二階・部分二階）を1か所に持つ
- **R-VERIFY-12** 型チェックを含むビルドとテストの両方が通らない状態で、変更を完了としない

## 17. 拡張の方針

### 17.1 原則

- **R-EXT-01** 拡張は、生成結果が変わるものなので、GEN_VERSION を上げ、設計相談を経て、別の変更として入れる
- **R-EXT-02** 拡張は、次の品質改善の優先順（R-EXT-05〜R-EXT-13）の順に行う。外形・方位の拡張は R-SCOPE-05 に従う
- **R-EXT-03** 拡張で足す要件は、この文書に ID 付きで加え、暫定の値は ［暫定］ と明記する

### 17.2 品質改善の優先順

1. **R-EXT-05** 部屋種別ごとの最小の短辺をハード制約にする（R-EVAL-16）。スコアで調整して残すことはしない
2. **R-EXT-06** 個室にクローゼットを付属させ、余った面積を収納へ回す（R-PROG-11、R-PROG-13）
3. **R-EXT-07** 廊下と階段の扱いを変える。全幅の中廊下をやめてホールを最小限にし（R-SPACE-04）、リビング階段も選べるようにする（R-STAIR-06）。階段まわりの扉は R-DOOR-14・R-DOOR-04・R-DOOR-13 に従う。固定3帯構成（R-SPACE-10）の変更を伴い、汎用スライシング木が前提になる可能性が高い。浮いた面積は LDK（ダイニングの置ける奥行）と玄関へ戻す。GEN_VERSION 6 は、固定3帯のままの増分方式で、階段の開口（R-DOOR-14）・上下で同じ 4×5/4×6 の折り返し（R-STAIR-01、R-STAIR-08）・ホール帯の端の吸収（R-SPACE-34）・動線のガード（R-FLOW-05）を実施した。リビング階段・直進階段・2階の全幅ホールの解消は残り（汎用スライシング木の導入後に、階段コア先行のテンプレートで扱う）
4. **R-EXT-08** 窓の評価を実態に近づける: 二面採光、通風の対角線、水回り・階段の窓（R-WIN-02〜R-WIN-04）
5. **R-EXT-09** 上下階の壁の一致（直下率）を測る（R-IDX-05）
6. **R-EXT-10** 家具が置けるかを品質の判定に入れる: ダイニングテーブル、ベッドが置けない案を落とす／減点する（R-EVAL-04）
7. **R-EXT-11** 3案の多様性を「考え方の違い」にする（R-SEL-05）
8. **R-EXT-12** 敷地を反映する: 駐車場・庭を配置に反映する。玄関アプローチと道路からの視線を含める（R-IN-05、R-IN-06）
9. **R-EXT-13** 洗濯動線を成立させる（R-FLOW-04）

### 17.3 その後の拡張候補

- **R-EXT-14** 外形・方位の拡張: L字外形、中庭型、北道路・東西道路
- **R-EXT-15** 3案が揃わない境界条件（0〜2案）の改善（R-INFEAS-09）
- **R-EXT-16** 汎用スライシング木（H/V 再帰分割）を導入するときは、木をイミュータブルに扱い、measure のキャッシュが古い値を返さないよう毎回新しく作る
- **R-EXT-04** 汎用スライシング木・L字外形を入れると、固定3帯では隣接しない部屋ペア（浴室と玄関、浴室と LDK など）が隣接しうる。そのときも、ドア除外表（R-DOOR-05）が正規形で効くことを検査する
- アイソメ表示、好みプリセット（家事動線重視、収納重視 など）は、拡張候補として挙げるにとどめ、要件にはしない
